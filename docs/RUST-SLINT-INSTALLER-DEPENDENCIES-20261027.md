# Установщик и зависимости — 27 октября 2026

Последующее поручение выполнено в [кандидате 0.1.30](RUST-SLINT-DEPENDENCY-UPGRADE-20261027.md): конфликт Pillow/Gradio и совместимое обновление Torch/Transformers закрыты в отдельной квалифицированной среде. Сводка ниже сохраняет исторические результаты 0.1.29; рабочая 0.1.28 не заменена.

**Статус согласованной цели: выполнена и проверена.** [Итоговая сверка артефактов и результатов](../work/installer-dependencies-20261027/result.json). Это не приёмка всей стабильной версии и не закрытие всех advisory внешних библиотек.

## Объём и результат

Локальный кандидат **0.1.29** предотвращает обнаруженное сохранение нового профиля в виртуальном кеше MSIX-хоста. Исправлена граница запуска, а не настройки Windows или ACL. Исполняемые файлы рабочей 0.1.28, её профиль, выбранные модели и Python-среды не заменялись. Коммит, push, публикация и аппаратная приёмка этим проходом не выполняются.

Цель: отказ до изменения постоянных данных в перенаправленном контексте, успешная установка из обычного Explorer, сохранение данных при update/rollback; затем аудит зависимостей и проверка совместимых исправлений на изолированной реальной ML-цепочке.

## Защита установщика

- `launch_context.rs` проверяет физическое имя автоматически удаляемого файла через `GetFinalPathNameByHandleW`. `GetCurrentPackageFullName` сам по себе недостаточен: наш дочерний процесс сообщал `NO_PACKAGE`, сохраняя перенаправление файлов.
- Проверяются **корни AppData и существующий родитель назначения**. Регрессия выявила, что проба только внутри уже существующей папки пропускала обновление: создание файла и создание новой подпапки имеют разные последствия виртуализации.
- Явный путь в `Local/Packages/<package>/LocalCache` также отклоняется как место постоянного профиля. Ошибка RU/EN предлагает открыть Setup или Кавычку из обычного Проводника; профиль не сбрасывается и не переносится автоматически.
- Guard стоит перед созданием installation owner/журнала, обновлением, открытием установленного профиля, startup probe, locator/настройкой recovery-бюджета. Мастер проверяет контекст до открытия интерфейса и системной интеграции. Полностью явные CLI-fixtures вне AppData остаются допустимыми.
- Проба создаётся с `FILE_FLAG_DELETE_ON_CLOSE`, уникальным именем и `create_new`; закрытие handle удаляет её и при ошибке. Ссылки назначения дополнительно ограничиваются существующими `no_link_chain` проверками.

Основы поведения Windows: [MSIX file redirection](https://learn.microsoft.com/en-us/windows/msix/desktop/desktop-to-uwp-behind-the-scenes), [GetCurrentPackageFullName](https://learn.microsoft.com/en-us/windows/win32/api/appmodel/nf-appmodel-getcurrentpackagefullname), [GetFinalPathNameByHandleW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getfinalpathnamebyhandlew). Это проверка воспроизведённого Windows-контекста, не универсальная классификация всех возможных сторонних sandbox-хостов.

## Зависимости: что изменено

Сверены **388 пар пакет/версия**: фактический Windows normal/build Rust-граф, два Python requirements и CPU/CUDA wheels из manifest. Rust-граф нового payload совпал с проверяемым inventory: **263 пары**; включение Win32 API не добавило crates. Идентификаторы-алиасы CVE/GHSA/PYSEC не считаются независимыми уязвимостями.

OSV до изменений отметил **13 пар**, после окончательных pins — **7**. Это совпадения версий с advisory, а не число эксплуатируемых ошибок приложения. Снимки, диапазоны, первичные ссылки и withdrawn-поля сохранены в локальных JSON; нулевой список уязвимостей не заявляется.

Базовый интерфейс/маскот/расписание работают на Rust + Slint + SQLite/Win32. Python/Torch относятся к дополнительной локальной генерации; текст Gemma GGUF выполняет llama.cpp, Cosy имеет отдельный слой зависимостей, Qwen — общий Python-набор. Основной избыточный участок — demo/web и training-зависимости ML-пакетов, в частности Gradio: Rust-интерфейсу они не нужны, но простое удаление нарушает заявленные зависимости Qwen-TTS и не является проверенным облегчением установки. Следующий этап должен отделить inference-набор с сохранением совместимости и корректных package metadata, а не просто сократить requirements до успешного импорта одного модуля.

В этом проходе обновлён **только собственный QA overlay**; пользовательские среды по-прежнему имеют прежние версии. Обновление EXE само по себе не обновляет эти библиотеки.

Полные списки ссылок каждого advisory — в снимке OSV.

## Оставшиеся совпадения и применимость

| Пакет/версия | Фактический путь и решение |
|---|---|
| Accelerate 1.12.0 | Advisory относится к sharded checkpoint loader и непроверенным `weight_map`. Прямой вызов этих функций приложением отсутствует; произвольные checkpoint indexes не поддерживаются. Перед загрузкой HF/Cosy теперь проверяются **все ожидаемые файлы по SHA-256 каталога**, включая configs/YAML/indexes/weights. 1.14.1 на PyPI отсутствует; версия библиотеки оставлена с этим ограничением, а не объявлена исправленной. |
| Transformers 4.57.3 (Qwen) | Нужна Qwen-TTS 0.1.1; переход на major 5 требует отдельной совместимости. Никакого Trainer, конвертации checkpoints, Donut/Marian/LightGlue, `save_pretrained` в пользовательском потоке нет. Загрузка локальная, `trust_remote_code=False`, `use_safetensors=True`; configs/tokenizers/weights проверены по каталожному SHA до загрузчика. Offline-переменные сохранены. Это ограничение входов, не исправление upstream. |
| Transformers 4.51.3 (Cosy) | Изолированный слой Cosy загружает встроенный Qwen2 encoder. Его YAML/config/safetensors/PT-файлы сверяются с каталогом до запуска; Cosy-worker запрещает сетевые соединения. Пользовательский голос/характер не становится конфигурацией Python-модели. Уязвимые training/conversion/image APIs не используются. Major 5 не подставлялся без квалификации. |
| Torch 2.9.1 | Cosy действительно вызывает `torch.load(weights_only=True)`; считать это само по себе достаточной защитой нельзя: PYSEC также описывает memory corruption weights-only unpickler. Каталожный SHA перед загрузкой теперь запрещает изменённый checkpoint даже того же размера. `lstm_cell`/`jit.script` не предоставлены как пользовательские операции; code export/train не запускаются. Torch/torchaudio/CUDA не обновлены несогласованно до 2.13. Риск старой библиотеки и необходимость отдельной квалификации новой пары сохраняются. |
| Pillow 12.3.0 | **Открытый долг совместимости.** Исправления требуют 13.0.0, но Gradio 6.17.3 и проверенная актуальная 6.30.0 требуют `<13`. Это конфликт разрешения зависимостей. Новый Rust UI обрабатывает визуальные пресеты Rust-декодером, worker загружает только голосовые аудиореференсы. Legacy `backend/server.py`/Python visual import всё ещё может вызвать Pillow на пользовательском изображении; этот отдельный старый вход нельзя считать безопасным по данному аудиту. Рекомендация: вынести Qwen demo/Gradio из inference-среды либо квалифицировать новый совместимый набор, затем обновить Pillow. Слепой `--no-deps` обход ограничения не применялся. |
| block-buffer 0.10.4 | OSV GHSA описывает повреждение **inline cursor** при пойманной panic и `ReadBuffer`. В зафиксированном исходнике 0.10.4 `pos: u8` — отдельное поле, `ReadBuffer` отсутствует; SHA2 использует собственный compression callback. По исходнику описанная предпосылка не совпадает с установленной реализацией. Зафиксировано как совпадение широкого диапазона с неподтверждённой применимостью; не скрыто из scan. |
| zip 0.6.6 | Три RUSTSEC касаются автоматических `ZipArchive::extract`/stream extraction, Unix modes и symlink targets. Наши package/profile/preset пути **не вызывают эти extract API**: есть поэлементные bounds/имена/SHA, отклонение links и создание обычных новых файлов, Unix permissions не применяются. Соответствующие malicious-archive регрессии входят в Rust-тесты. Версия оставлена; это доказательство по текущим вызовам, не утверждение безопасности всех API crate. |

Источники оставшихся границ: [Accelerate](https://github.com/huggingface/accelerate/issues/4067), [Transformers config/code](https://github.com/advisories/GHSA-29pf-2h5f-8g72), [Torch advisory](https://github.com/advisories/GHSA-qfhq-4f3w-5fph), [block-buffer](https://github.com/RustCrypto/utils/security/advisories/GHSA-qwgh-2vcv-g2f7), [zip](https://rustsec.org/advisories/RUSTSEC-2026-0368.html). Точные диапазоны, aliases и первичные references для всех Pillow/Torch/Transformers совпадений сохранены в `final-audit/advisories.json`.

## Границы готовности

Закрывается конкретный кодовый пробел установщика и выполнен разбор зависимостей с шестью совместимыми обновлениями. **P4–P8 целиком не закрываются**: отложенные батарея/смена Windows-сессии/мониторы, целевой ноутбук, чистая ОС/реальный ENOSPC, сутки, полный stable update, лицензии и подпись остаются в прежнем реестре. Устранение всех upstream advisory и всех legacy-зависимостей не заявляется. Следующий крупный шаг по зависимостям — отдельная inference-среда без demo/training-набора и совместимое обновление Torch/Transformers/Pillow.

Пользовательские пресеты/голоса/данные в артефакт не включены. Опубликованный Rust-prerelease и рабочая установленная версия остаются **0.1.28**; stable-канал не переключался. Кандидат 0.1.29 собран локально: [Setup](../outputs/next/0.1.29-candidate-02/Kavychka-Next-Setup.exe), SHA-256 `3a75c19070f5d6fde69118909194d8f29dfed40e28ea7f6b50659b07afe19f23`; payload `app.exe` — `7effd38a061ce8e2a61bad582bded3430c48d59b4c121e48ca91a94a91253ebe`. Его установка в рабочую папку или публикация — отдельное действие. Промежуточный `0.1.29-candidate` не является итогом: его отрицательная проверка существующего профиля выявила неполную защиту, исправленную в `candidate-02`.
