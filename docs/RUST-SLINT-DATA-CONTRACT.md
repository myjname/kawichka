# Контракты первого этапа Rust-переноса

**Действующая редакция 2:** [контракт P1](RUST-SLINT-P1-CONTRACT.md) и [его приёмка](RUST-SLINT-P1-ACCEPTANCE.md). Они заменяют промежуточные формулировки ниже, включая устаревшие «пока не реализовано» и прежний остаток P1. Ниже сохранена история развития редакции 1, а не второй действующий контракт. Общий остаток P2–P8: [аудит](RUST-SLINT-PLAN-AUDIT.md).

Дополнение этапа установки от 23.10.2026: [актуальный отчёт](RUST-SLINT-MIGRATION-INSTALL-UPDATES.md). Его уточнения имеют приоритет над историческими отметками «не реализовано» ниже: именованные часовые пояса, активные независимые пресеты и старый checkpoint подключены; лимит карантина/резервов настраивается, очистка по 7 дням реализована. Полное восстановление архива профиля и все аварийные проверки ещё открыты.

В установленной Next-версии рабочий Sandbox находится в <common>/.kavychka-next. Только эта принадлежащая приложению вложенность допускается для первого импорта; произвольные вложенные назначения запрещены. Оригинал WinForms не открывается через SQLite для записи. Новые модели/среды находятся в components рабочей библиотеки; существующие исходные веса читаются по прежним путям. При обычном обновлении Current.common/data не меняются. Перенос на новый диск после установки — отдельная ещё не завершённая операция.

Программа: install.owner, install.lock, versions/<semver>, current.json и transaction.json. Журнал хранит previous/candidate, путь проверенной резервной копии и лимит восстановления. Переключение current.json происходит только после проверки установленного пакета и успешного --prepare-install с совпадающей скомпилированной версией. Резерв включает SQLite backup, настройки и медиа с манифестом SHA-256, исключает components/cache/jobs и веса. Незавершённый переход повторно восстанавливается из проверенного резерва; новая работа сохраняется отдельно. Копия повреждённой новой БД помечается forensic и не выдаётся за исправную SQLite-копию.

Формат .kavychka остаётся data-only ZIP: ограниченные размеры, число файлов, разрешённые медиатипы, проверенные относительные пути и отдельные character/voice/visual metadata. Неизвестные поля не экспортируются обратно. Перенесённый пароль/API-токен не становится настройкой Next.

Редакция 1, 23 октября 2026 года. Применяется к отдельному проекту next. Реализация разрешена; рабочая установка автоматически не переключается. Полные требования: [план](RUST-SLINT-MIGRATION-PLAN.md).

## Границы ответственности

Rust владеет правилами и целевыми настройками. UI не является источником состояния. Вычислительный процесс получит снимок настроек и задачу, вернёт результат; он не будет параллельным владельцем SQLite. Движки и модели сейчас не переписываются.

Этот этап реализует **пробный захват и проверку**, а не окончательное переключение, слияние всех исторических установок, полный архив отката или загрузку моделей.

## Действующий источник

Указатель %LOCALAPPDATA%/Kavychka-storage.json читается с прежним полем directory. При недоступной выбранной папке — ошибка; нового хранилища и загрузок на C нет. Без указателя возвращается прежний стандартный путь без создания папки.

Консоль требует явного --source и сама не выбирает личные данные для тестирования. Для пробного захвата исходник и назначение должны быть отдельными, без вложения друг в друга. Производственное поколение данных внутри общего корня и переключатель активной версии относятся к следующей операции; нельзя просто заменить указатель на папку preview.

## Настройки

SettingsSnapshot.format = 1:

- desktop: разрешённые старые поля JSON и согласованные общие предпочтения;
- inference: расширенные параметры SQLite; общие поля убраны отсюда, чтобы не создавать второго изменяемого владельца;
- ignored_desktop_fields / ignored_inference_fields: имена неподдержанных полей без их значений.

Правила для TextModel/text_model, RuntimeTextModel/runtime_text_model, VoiceModel/tts_model, Swear/swear и RuntimeGeneration/runtime:

1. Если BackendSettingsMigrated = true, сохраняется JSON.
2. Пока импорт не завершён, SQLite используется для полей без ручного переопределения в BackendSettingsOverrides.
3. Ручной выбор JSON не откатывается поздним ответом старого backend.
4. AutomaticPreparation/auto_daily и AutoKeepDaily/daily_auto_keep используют независимый BackendDailySettingsMigrated.
5. Если источник поля отсутствует, используется сохранившийся второй источник либо известное прежнее значение по умолчанию.

Современные SpeechLanguage, VoiceProfile, AddressForm и UserName имеют приоритет JSON; при отсутствии берутся из SQLite. Старое character_description сохраняется в inference, даже если ещё не создан отдельный пресет. Выбор CharacterFile сохраняется независимо.

Сохраняются timezone ID, даты и история. Microsoft JSON-даты пока хранятся без изменения; это не доказательство готовности нового системного преобразования часовых поясов или восстановления серии.

Применяется разрешённый список полей. Старые API-ключи и неизвестные значения не переносятся в активные настройки. Будущая SchemaVersion JSON отвергается; явные некорректные параметры не заменяются молча стандартными.

## Пробная база

Исходные таблицы settings, phrases, plans, voice_rotation и preparation сохраняются через SQLite backup в library.snapshot.sqlite3. Текущие известные строки и дополнительные столбцы этих таблиц сохраняются; неизвестные таблицы, представления, триггеры и будущая user_version требуют отдельного контракта, а не молчаливого импорта.

Новая база получает user_version = 3 и таблицу app_settings с единственным SettingsSnapshot. Прежняя таблица settings очищается после переноса разрешённых значений. secure_delete и VACUUM удаляют старые значения из новой копии; исходная база не меняется. Снимок остаётся пробным, его нельзя передавать старому Python Store в качестве уже совместимого корня.

Проверяются целостность, число строк, локальность audio_path и наличие записей для живых ссылок. Исчезнувшее исходное аудио не объявляется успешно перенесённым. Удалённые/исключённые строки и несвязанные аудиофайлы сохраняются: видимая очередь не равна всей библиотеке.

## Файлы и компоненты

В набор захвата входят settings.json, библиотека с WAL/SHM, audio, presets, builtin-days, reminder-state.json и legacy-personalization.json. Модели и среды не копируются.

Для исходных файлов собираются относительный путь, длина и SHA-256. При изменении источника незавершённая копия не смешивается с новым состоянием. Каталоги-ссылки, reparse points, выходы путей и несвязанные непустые назначения отвергаются.

Явные model_paths сохраняются без переписывания. Найденные стандартные папки моделей регистрируются с исходными путями в отчёте. Существование папки не означает, что модель или вычислительная среда уже прошли проверку запуска.

Пресеты и журнал на этом этапе сохраняются как данные с проверкой байтов. Полная семантическая проверка каждого пресета, нормализация медиа и преобразование журнала в рабочую Rust-серию остаются последующими задачами, не считаются выполненными копированием.

## Согласованность, отмена и повтор

1. Производственный вызов держит прежний mutex Local/KavychkaBreaks-v1; уже работающая «Кавычка» не закрывается автоматически.
2. Чтение оригиналов в Windows запрещает одновременную запись/удаление на время открытия. SQLite не открывает оригинал: даже read-only WAL-соединение может использовать SHM. Вместо этого DB/WAL/SHM захватываются в частную папку capture.
3. SQLite backup работает только с частным захватом. Применение [Backup API](https://sqlite.org/backup.html) обеспечивает согласованный снимок базы; [rusqlite backup](https://docs.rs/rusqlite/0.40.2/rusqlite/backup/index.html) используется пошагово, с проверкой отмены.
4. Назначение защищено отдельной файловой блокировкой. Журнал format = 1 хранит полный отпечаток источника и этап capturing/copying/verifying/ready. В Windows смена файла журнала атомарна с заменой.
5. Отмена оставляет незавершённое состояние; готовый отчёт не публикуется. Повтор с тем же источником проверяет уже скопированные файлы, заново создаёт снимок БД и не добавляет дублирующие строки.
6. После сверки исходных отпечатков, строк и файлов raw-capture с прежними настройками/базой удаляется из готового назначения. Личные оригиналы остаются нетронутыми.
7. Preview-ready означает только успешное завершение этой операции. Переключение, совместимость с полноценным UI/worker, реальные модели и откат ещё не подтверждены.

Дисковый бюджет: по умолчанию 2 ГБ, без весов; итоговый набор с метаданными не должен превысить лимит. Отдельно оценивается пиковое место для capture/backup/VACUUM. Полная политика хранения двух версий до 7 дней и карантин ежедневной очистки будут реализованы в обслуживании, а не имитируются наличием одной preview-папки.

## Напоминания

Чистые правила используют переданное время и не выполняют системный ввод/звук:

- Первичные события выше повторов; еда → разминка → перерыв; затем более раннее время и устойчивый ID.
- Совпавшие первичные еда+перерыв объединяются, сохраняя оба ID. Остальные пары не объединяются без дополнительного правила.
- Не показанное событие допускается до 5 минут включительно. Это не таймер закрытия уже показанного сообщения.
- Runtime-предел по умолчанию 10 секунд от события, включая очередь вычисления/запуск; повторная попытка не сбрасывает его.
- После сбоя актуальный показанный, но не подтверждённый текст восстанавливается тихо. Нельзя достоверно восстановить факт услышанного физического звука только по транзакции БД.
- Исключение для «Не беспокоить» не отменяет блокировку и пользовательскую паузу. Само определение системного состояния ещё не реализовано.

## Непроверенные границы

### Изолированные настройки оболочки P3 — исторический контракт до подключения библиотеки

Новый UI пока не открывает library.snapshot.sqlite3 или действующую библиотеку. Для проверки служит отдельный каталог с меткой shell-sandbox.owner = kavychka-shell-sandbox-v1, эксклюзивной блокировкой shell.lock и shell.sqlite3. Текущий user_version 2 добавляет reminder_state к прежней версии 1. В preferences хранится одна типизированная JSON-запись format 1; в reminder_state — версия 1 состояния координатора. Работа с SQLite выполняется одним отдельным потоком; main/UI не являются вторым владельцем записи.

В настройки входят расписание, тема, независимые языки UI/речи, имя, параметры активности и дополнительные настройки напоминаний. Состояние включает доставленные/подавленные ID, неподтверждённые сообщения, бюджеты повторов, отметки и время завтрака, его таймер разминки, паузу, положение маскота и счётчик ручных действий. Добавочные поля имеют совместимые значения по умолчанию для прежних пробных баз. Некорректные/неизвестные версии и поля отклоняются без сброса.

Настройки и состояние фиксируются одной транзакцией до выдачи сообщения/звука. Проверен отказ второй записи с откатом первой. Черновик настроек применяется к текущей версии по отличающимся полям: несвязанное изменение из трея не теряется при сохранении давно открытого окна. Короткое восстановление показывает сохранённый текст тихо, не выдаёт ту же первичную фразу второй раз и сохраняет бюджет повторов.

Это промежуточный контракт отдельной Rust-версии, **не завершённое преобразование SettingsSnapshot в рабочую установку**. Для подключения миграции требуется явный конвертер и сверка всех сохранённых полей; отсутствие настройки в текущем окне не разрешает удалить её при переносе.

Оболочка требует явный абсолютный путь. Непустой каталог без метки песочницы, ссылки/reparse points и вторая запись в ту же песочницу отклоняются. Общий указатель Kavychka-storage.json не читается и не меняется; веса не ищутся и не скачиваются. Поэтому пробный запуск не проверяет автоматический подхват реального хранилища.

### Рабочая библиотека и модели, 23.10.2026

Текущий shell.sqlite3 имеет user_version = 3: preferences, reminder_state, рабочие phrases, library_meta и delivery_claims. Старые shell-версии 1/2 обновляются добавочно; будущая версия отвергается. Единственным владельцем записи остаётся Rust-поток координатора. Python получает версионированный JSON-снимок задания и возвращает сообщения о прогрессе/тексте/аудио/результате; доступа к SQLite у него нет.

При первом запуске launcher читает прежний указатель хранилища либо стандартный путь. bootstrap_legacy использует прежний проверенный захват под LegacyGuard и создаёт личный снимок в legacy. Полный разрешённый SettingsSnapshot, старые планы/подготовка/ротация и дополнительные поддержанные столбцы сохраняются в архивном снимке. В рабочую модель конвертируются настройки расписания, темы, языков, активности/повторов, модели, описание персонажа, голосовой профиль и подачи. Неизвестные ключи и API-секреты не становятся рабочими настройками. Отсутствие поля в UI не удаляет его из разрешённого снимка.

Импорт выполняется один раз; повторное открытие сохраняет новые настройки Rust-версии и не добавляет старые строки повторно. Это не синхронизация двух приложений. Кешированная копия может открыться при недоступном исходном диске, но отсутствующая модель получает явную ошибку. Общий указатель не меняется. Модели и среды читаются по прежним путям, личные пресеты/аудио копируются в отдельные данные.

Тексты, ID, статусы отбора и история использования сохраняются; builtin-days и старая история дополнительно защищают от повторов. Точные совпадения проверяются по всей истории, близкие шаблоны — по последним 500 строкам. Старые отметки и скрытые строки не превращаются в новую очередь. Прослушивание не расходует фразу. Выбор записи, claim, настройки и состояние напоминания фиксируются одной транзакцией до физической выдачи; отказ откатывает всю запись.

Результат генерации принимается построчно: сначала проверенное аудио из временной папки, затем транзакция строки/назначения/ротации. Частичный текст переживает ошибку озвучки. Ручные черновики не становятся одобренными вследствие автоматической подготовки дня. Переозвучка сохраняет ID/текст и обновляет только голосовые поля; пользовательский отбор во время задания не затирается ответом worker. Ошибка/отмена уничтожает собственное дерево процессов, оставляя журнал и принятый результат.

Runtime-предел отсчитывается от времени первичного события или наступления повтора, включая ожидание в очереди, а не от старта модели. После предела используется готовый/встроенный вариант; поздняя генерация не подменяет уже показанное сообщение. Подготовка дня учитывает расписание и питание, может идти при блокировке без звука. Без моделей она использует встроенный конечный банк текстов и голос Windows, без Python.

Старые дневные аудиофайлы удаляются из активной библиотеки только после безопасного помещения в карантин; текст/история и референсы пресетов остаются. Промежуточные файлы принятого задания убираются только внутри собственной проверенной папки jobs. Начальный предел карантина фиксирован в 2 ГБ; переполнение не разрешает потерять последнюю копию. Автоочистка карантина по 7 дням и пользовательская настройка лимита ещё не реализованы.

Подтверждённый путь воспроизведения — FLAC через Rust-декодер и WASAPI, с сохранением частоты; Windows SAPI служит системным голосом. ZIP содержит фразы и их аудио, а не весь профиль приложения. Установка новых весов ограничена выбранным компонентом; новая среда нейроозвучки и полноценный установщик остаются отдельным этапом. Полная семантика старого checkpoint напоминаний, произвольных именованных часовых поясов и визуальных пресетов пока сохранена как исходные данные, но не полностью активирована.

### Остаток P1 и последующих этапов

Для полноты P1/следующих этапов ещё нужны: критические точки аварийного прерывания первого создания журнала; проверка настоящего ENOSPC, reparse points и отказов доступа; полная миграция старых схем; полная семантика пресетов/журнала; переключение и обратимый журнал пользовательских изменений. IPC и реальная библиотека на согласованной копии уже проверены в текущем этапе, см. [отчёт](RUST-SLINT-MODELS-LIBRARY.md). Контрольный ноутбук отсутствует. Оставшиеся пункты нельзя закрыть текущими модульными тестами.
