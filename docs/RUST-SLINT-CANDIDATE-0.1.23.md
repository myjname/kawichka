# 0.1.23 — кодовые остатки перед приёмкой

25 октября 2026. [Поручение и объём](RUST-SLINT-CODE-COMPLETION.md): сначала завершить код, приёмку проводить в конце. Названные кодовые пробелы актуального реестра закрыты, подготовлен единый кандидат. Это **готовность к приёмке**, не завершение P5–P8 и не опубликованный стабильный выпуск.

## Изменения

**G04 — начала фраз.** `diversity.py` объединяет «Ты / Твой / Твоя / Твои» и `you / your` в семьи. Если слово/семья встречалось минимум три раза в последних восьми репликах, prompt просит другую конструкцию. Дневная партия предпочитает новое начало в пределах прежних шести попыток.

Это мягкое предпочтение: фраза, прошедшая прежние проверки темы/языка/длины/мата/дублей, остаётся резервом. Она не теряется при исчерпании стилевых попыток или штатном отказе дополнительного запроса модели/транспорта. Hard-rejection не попадает в резерв; отмена не выдаёт его пользователю. В runtime остаётся подсказка по истории, но **нет дополнительных запросов только ради стиля** после получения пригодного уникального текста. Worker явно передаёт политику задачи независимо от общей настройки runtime.

Английский prompt теперь тоже использует шесть структурных вариантов. Из указаний рода удалены примеры «ты устала / ты поела», похожие на заданные факты. Сохранённое описание персонажа не заменяется. Изменены `backend/kavychka_local/{character,diversity,engine}.py` и `next/worker.py`.

**O01/P7 — применение обновления.** Перед перезапуском видна сводка версий, резервирования настроек/библиотеки, сохранения моделей/референсов и остановки фоновой генерации. Повторная проверка пакета теперь выполняется в фоне **до выхода**. Read-guard удерживает файл от записи/замены до запуска установщика; повреждённый кеш оставляет приложение открытым. Если пока считался SHA началось сохранение/импорт/перенос, перезапуск не ставится скрыто в очередь на будущий выход. Изменены `app/src/updater.rs` и `ui/app.slint`; расписание, схема библиотеки и пути не менялись.

**P7 — цепочка релиза.** `.github/workflows/next-windows.yml` проверяет точный стабильный tag `next-vX.Y.Z` до сборки и встраивает его версию в EXE. После проверок создаётся **черновик** из артефактов того же run; write-права есть только у tag-push job после verify. PR-проверка остаётся read-only. Добавлены общий Cargo-кеш стадий, создание тестовой work-папки и новые регрессии.

`next/tools/verify_release.py` без выполнения installer проверяет envelope/ZIP SHA, платформу/версию manifest, размеры и SHA всех файлов, состав portable и тождество setup в обоих артефактах. Несовпадающий существующий `SHA256SUMS.txt` не переписывается. Workflow дополнительно сверяет SHA/размер загруженных GitHub assets — именно эти поля использует updater. При неподтверждённом digest черновик не публикуется. Тег с суффиксом, переносом строки, ведущими нулями или неправильным префиксом отвергается.

Финальная публикация остаётся после приёмки. В этой работе Actions/tag/release не запускались и не создавались. Контракты CLI: [создание draft](https://cli.github.com/manual/gh_release_create), [получение артефакта run](https://cli.github.com/manual/gh_run_download).

**M06/B18 — подсказки и имена.** Импорт перечисляет реальные пределы GIF: до 300 кадров и суммарно 40 млн декодированных пикселей. Декодер/пределы не менялись. Локализованные accessibility-имена добавлены динамическим полям инструкции подачи, типа/файла импорта, имени пресета, референса и формата внешности. Сводка обновления допускает рост высоты по тексту.
