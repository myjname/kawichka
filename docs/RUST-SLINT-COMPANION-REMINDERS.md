# Этап: маскот, трей и напоминания

23.10.2026 пользователь явно попросил подключить эти функции, создать цель и довести этап до проверенного результата. Этап реализован; перечисленные ниже проверки пройдены. Это завершение отдельного этапа, а не всей миграции.

Объём: базовый Rust + Slint без ML, отдельное хранилище; маскот, сообщение, нативный трей, независимый от окна настроек цикл; расписание, подтверждение и повторы по активности; паузы, ежедневная разминка после завтрака и ручная разминка. Состояние фиксируется до показа/звука, короткий перезапуск восстанавливает текст тихо. Старая установка не переключается.

Проверки готовности этапа:

- [x] Правила координатора с управляемыми временем/вводом: приоритет, подтверждение, повторы, отдых, пауза, восстановление, отсутствие очереди после блокировки/сна.
- [x] Атомарное сохранение настроек и состояния; отклонение повреждённых/будущих данных без сброса.
- [x] Настройки закрываются в фон; открываются повторно из настоящего трея/маскота; явный выход завершает собственные потоки.
- [x] Настоящие окна Windows: topmost/tool/noactivate, обрезанные прозрачные углы, сообщение и подтверждение; повторные открытия без disposed-сбоев.
- [x] Настоящая регистрация и callback трея; восстановление утраченной регистрации собственного значка.
- [x] Базовые сигнал и системная озвучка; отсутствие нужного языка голоса объясняется, данные не скачиваются. Отмена и закреплённый на время проигрывания WASAPI endpoint.
- [x] Нативный связный сценарий от расписания до подтверждения и повторов, настоящий перезапуск, тесты и Clippy.

Границы: этот этап не является завершением P3–P8 или всей миграции. ML/библиотека/подхват действующей установки/обновления остаются следующими этапами. Точные системные «Не беспокоить», физическое отключение наушников, матрица DPI/мониторов, аппаратные ресурсы и суточная стабильность требуют самостоятельных проверок; наличие SHQueryUserNotificationState не доказывает интеграцию с современным Windows DND. Источник: [документация API](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shqueryusernotificationstate).

Код: core/engine.rs — решения, service.rs — единственный SQLite-владелец и цикл, shell.rs — только представление, platform — Win32 raw input/окна/звук/время. Нативные QA-действия ограничены собственными окнами/значком процесса. Реальные пользовательские данные не используются как тестовая фикстура.

## Что доступно

- Перетаскиваемый маскот «кавычка», сообщение с подтверждением, скрытие маскота и повторное открытие настроек через маскота или трей. Закрытие настроек оставляет фоновый цикл; явный выход завершает приложение.
- Расписание, объединение совместимых еды/перерыва, три разные дразнящие реплики повторов, пауза на время или до завтра. Последняя шутка ничего не выключает. Показанное сообщение сохраняется до подтверждения; отдельный просмотр не тратит повторы.
- Отдых проверяется по мыши/клавиатуре с настраиваемыми порогами. По умолчанию подтверждение не доказывает отдых. Неактивность до нового события не засчитывается; продолжающийся отдых завершает серию после её собственного периода.
- Ручная разминка независимо от расписания и автоматический таймер после отметки завтрака, включая выходные. Повторная отметка завтрака не сбрасывает таймер.
- Отдельные настройки изображения/звука поверх полного экрана, RU/EN, светлая/тёмная/системная тема. Базовая озвучка использует установленный голос Windows; ML ещё не подключён.
- Состояние и настройки записываются одной транзакцией до показа. Короткий перезапуск тихо восстанавливает сообщение и бюджет повторов; черновик настроек не затирает независимое изменение из трея.

## Запуск

Двойной клик по [next/Start-preview.bat](../next/Start-preview.bat). Корневой Start.bat по-прежнему запускает старое приложение.

Новая версия работает с отдельными данными work/slint-shell-user-preview. Сохранённые настройки preview подхватываются повторно; действующие модели, записи и общая папка старого приложения не переключаются. При актуальной локальной сборке батник не вызывает Cargo и не скачивает зависимости. На чистом клоне для первой сборки нужны Rust MSVC и C++ Build Tools.

Повторить нативные проверки на отдельных синтетических данных:

```powershell
.\next\Start-preview.bat -Offline -Verify -VerifyAudio
```

Нужен готовый кеш зависимостей и обычный интерактивный сеанс Windows с Explorer. Изолированная среда Codex отклоняла регистрацию трея; итоговая проверка выполнена вне этого ограничения, без требования запуска приложения администратором.
