## Отдельный кандидат

Набор ранее выполненных ручных проверок [Check-P4.bat, кандидат 0.1.9](../work/raster-fix-20261024/manual-candidate/Check-P4.bat) проверяет SHA файлов подготовленного набора, создаёт **новую** папку work/p4-manual-runs и открывает в ней копию кандидата. SHA-256 EXE: `4406d60d4ff2fe1485682281af9bf1a46b67996334783c43aa71a484bdc034c6`. Рабочая установка и личная библиотека не открываются. Модели/Python не нужны, сеть и загрузки не требуются. Это отдельный тестовый набор, не публичный выпуск.

Частичные физические результаты 24 октября: повтор при продолжении ввода; прекращение повторов после 75 секунд без ввода и возвращения; голос повтора в QA-режиме All; речь остановилась при Win+L и не возобновилась после разблокировки. У 0.1.8 устранён возврат заголовков при кликах, но найден срез края; в 0.1.9 пользователь подтвердил ровный край и исчезновение обрезания после кликов (запуск `20261024-112756-a2a4fce1`). В том же запуске при переключении аудиовыхода Windows озвучка из библиотеки остановилась и на другом выходе не продолжилась. После возврата выхода самопроизвольного replay не было, новое явное прослушивание работает.

При отключении/подключении устройства пользователь также наблюдал остановку без перехода на другой выход и отсутствие автоматического replay. **Закреплённый режим этих попыток не подтверждён:** позднее пользователь уточнил, что мог оставить системный выбор. После перезапуска интерфейс показывал «Как в системе», сохранённый ID был пустым. Это не доказательство сброса настройки и не успешная проверка закреплённого режима. Повторяем с явным выбором, сохранением и проверкой непустого ID до отключения. Подробнее — [отчёт оформления](RUST-SLINT-OVERLAY-FRAME-FIX.md).

При повторной попытке пользователь явно выбрал и сохранил конкретное устройство. Чтение тестовой базы подтвердило непустой ID; после отключения устройства, выхода через трей и повторного запуска той же 0.1.9 с теми же данными сохранённый ID совпал с исходным (сравнение по SHA-256 без вывода идентификатора). Пользователь подтвердил отображение недоступного выбора и тишину при явном прослушивании. Эта проверка сохранения выбора пройдена. Пользователь затем уточнил: устройство лишь остаётся в списке Windows, звук через него недоступен; противоречия с показанием Кавычки нет. Приложение перечисляет только активные render endpoints (`DEVICE_STATE_ACTIVE`); видимость записи в Windows не равна активности endpoint.

Отдельно пользователь проверил Bluetooth-наушники и сообщил, что после их отключения Кавычка показывает недоступное устройство. Это подтверждает наблюдаемое состояние интерфейса для Bluetooth. Дополнительные результаты воспроизведения или сохранения именно Bluetooth-выбора из этой реплики не выводятся.

Пауза при ручном прослушивании: пользователь подтвердил, что слышимая длинная фраза остановилась по «Пауза · минут» и не запустилась сама после «Продолжить». Эта проверка пройдена; поведение Windows «Не беспокоить» этим не проверено.

Доверие подтверждению: пользователь включил «Доверять отметке без проверки отдыха», сохранил, подтвердил новую разминку и активно пользовался ПК 75 секунд. Повторов не было. При записи результата тестовая база подтверждала `trust_confirmation=true`, повтор/неактивность по одной минуте. Это положительный сценарий этой настройки; допуск случайных кликов проверяется отдельно.

Сон: в сценарии запрошенного сна на 15–20 секунд пользователь сообщил, что речь остановилась при входе в сон и после возвращения не воспроизводилась. Затем подтвердил новый повтор после 75 секунд активной работы мышью/клавиатурой. В следующем сценарии, после подтверждения повтора, запрошенного сна минимум на 75 секунд и ещё 75 секунд активной работы, новых повторов той же разминки не было. Оба сценария пройдены по наблюдениям пользователя; фактическая длительность сна отдельно не измерялась. Это не проверка всех моделей сна/гибернации и конфигураций оборудования.

Оконный режим перед fullscreen: пользователь установил обычный звук «Сигнал и голос», fullscreen-звук «Тишина» и подтвердил голос повтора при активной работе в обычном окне браузера. Сохранённые настройки тестовой базы при записи результата: `all / silent / both`. Прежнее отсутствие голоса в оконном режиме в этой попытке не воспроизвелось; его исходная причина не установлена.

Ручной блок в браузерном F11 пройден по наблюдениям пользователя во всех четырёх выбранных сочетаниях:

| Видимость | Звук | Наблюдение |
|---|---|---|
| Маскот с сообщением | Тишина | Маскот и повторное сообщение, без звука |
| Только сообщение | Только сигнал | Сообщение и сигнал, без маскота и голоса |
| Ничего | Только голос | Голос без сигнала и элементов поверх браузера |
| Маскот с сообщением | Сигнал и голос | Маскот, сообщение, сигнал и голос |

Первая попытка варианта 3 была неопределённой: пользователь не услышал голос после 75 секунд, но в настройках стоял интервал **4 минуты**. После явного выбора одной минуты повтор варианта 3 прошёл; дефект звука не установлен. Каждый режим встретился хотя бы раз; эти четыре сочетания не подменяют все 12 комбинаций, эксклюзивный fullscreen или другую аппаратную конфигурацию.

Исходные настройки тестового набора: русский интерфейс и голос Windows, нейтральные синтетические тексты, никаких личных пресетов; автоподготовка выключена, расписание рабочих дней пустое, напоминания вызываются кнопкой «Разминка сейчас». Неактивность и повтор — по минуте, два случайных клика допускаются, подтверждению без отдыха не доверяем. В библиотеке два выбранных коротких текста для напоминаний и два невыбранных длинных «Проверка номер…» для явного прослушивания и переключения звука. В исходном QA-шаблоне fullscreen audio установлен в All, чтобы отдельно проверить речь; в текущем ручном запуске настройки меняются пользователем для описанных выше сценариев. Это не изменение производственного default. Первый ручной вызов расходует готовый текст, «Прослушать» не расходует его. В этом наборе используется системный голос Windows; готовых аудиофайлов в тестовой библиотеке нет. Дата текстов обновляется только в новой синтетической копии при каждом запуске, чтобы проверка работала и в другой день.

Перед проверкой заверши другую тестовую копию через «Выход», чтобы не путать маскотов. Для выхода из этого кандидата используй «Выход» в трее: обычный крестик оставляет приложение в фоне. После выхода собственные worker/аудиопотоки должны завершиться. Скрипт не блокирует экран, не переводит ПК в сон, не переключает сессии и устройства — эти действия выполняет человек в удобный момент.

## Что проверить и записать

Для каждой строки нужны наблюдение и результат, а при ошибке — конкретный шаг, приблизительное время и снимок окна. «Не проверялось» допустимо; такой пункт остаётся открытым. Не отправляй тексты личных фраз, ключи, полный дамп настроек или частные пути. Запуск оставляет локальную папку с идентификатором и SHA кандидата; сообщи только имя запуска и выбранные тесты.

| Проверка | Действия | Ожидаемый результат |
|---|---|---|
| Физическая клавиатура, мышь, колесо | Вызвать разминку, подтвердить сообщение и продолжать пользоваться клавиатурой/колесом/мышью более минуты | При «не доверять» появляется новый повтор, а не та же первичная выдача; всего не больше трёх повторов |
| Настоящий отдых и допуск кликов | В новой серии оставить ПК без ввода минимум на минуту; отдельно повторить с одним-двумя случайными кликами и без движения мыши/клавиатуры/колеса. Затем попробовать сверх допуска | Завершённый отдых прекращает повторы. Ввод сверх допуска не считается отдыхом. Отдельно проверить «доверять»: подтверждение сразу завершает серию |
| Настоящая блокировка | Вызвать длинное напоминание и нажать Win+L; вернуться сначала раньше минуты, в отдельной серии — позже | Под блокировкой звук прекращается. После возврата нет автоматического replay и накопленного залпа; неизвестный/заблокированный ввод сам по себе не засчитывается отдыхом |
| Настоящий сон | При активной серии вручную усыпить ПК; проверить короткий сон и сон длиннее минуты | После пробуждения нет replay/залпа; подтверждённый длинный сон завершает отдых, короткий не подменяет полный отдых |
| Смена сессии | Если есть второй локальный пользователь: переключиться при активной серии и вернуться | Нет вывода в недоступном сеансе, после возвращения нет очереди. Отсутствие другой учётной записи не считать успешной проверкой |
| Fullscreen | Оконный fullscreen, затем доступный эксклюзивный режим; отдельно менять видимость «маскот и сообщение / сообщение / ничего» и четыре режима звука | Следует выбранному сочетанию; приложение не захватывает фокус. Наличие проверки оконного fullscreen не доказывает эксклюзивный |
| Default и закреплённый звук | В настройках выбрать системный выход, затем конкретный; воспроизводить длинный текст и менять default/отключать выход при запуске, сигнале и речи | Текущий звук останавливается и не переезжает на другой выход. Текст остаётся. При повторном подключении нет автоматического replay; следующий явный вызов следует выбору. Недоступный pin сохраняется после перезапуска |
| Пауза и ограничение Windows | Во время речи включить паузу в приложении; отдельно включить Windows «Не беспокоить», сравнить с явным исключением и с блокировкой/паузой | Пауза даёт тишину без replay. Точное определение переключателя Windows **не обещается**; ограничение явно объясняется в мастере/настройках. Исключение для сообщённого Windows запрета не отменяет прочие правила |
| AC ↔ батарея | **Только ноутбук с батареей.** Снять и вернуть питание; проверить обычную новую партию, явное разовое разрешение, следующую обычную партию | Базовые напоминания работают; AC-only не сбрасывается разовым разрешением; автоматические задачи не стартуют без питания. Не отключать сетевой кабель питания стационарного ПК ради этого теста |

Настоящие ML-переходы между стадиями text/audio/result и подтверждение безопасной кооперативной отмены относятся к P6: их выполненный объём и границы описаны в отчёте P6–P8, без подмены ими аппаратной приёмки P4. Долговременная работа и ноутбук 8 ГБ относятся к P8. Физические строки P4 выше остаются в P4, пока нет достаточного свидетельства.
