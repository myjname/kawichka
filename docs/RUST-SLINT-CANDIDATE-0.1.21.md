## Исправление

При недоступном трее `Shell::present` возвращался до применения состояния сервиса: маскот и сообщения не показывались, настройки открывались повторно. Ошибка воспроизведена на отдельном неактивном desktop без Explorer; такой отказ создания трея также возможен до готовности Explorer при входе в систему.

В `shell.rs` отказ трея теперь не блокирует обработку состояния и показ напоминания. Повторное создание ограничено одной попыткой в пять секунд; действующий объект заменяется только после успешного создания нового. Управление меню выполняется при наличии трея. Проверка физического перезапуска Explorer на пользовательском desktop не проводилась.

В финальном native self-test 0.1.21 маскот виден, главное окно само не открывается, тихое напоминание показано и подтверждено, выполнены два сохранения и три minimize/restore. Это двенадцатисекундная проверка регрессии, а не суточная устойчивость.

### Как проверялось ограничение сети

Использован официальный Microsoft MXC 1.0.1 и системный Process Security Environment, в режиме блокирования, без permissive audit. На хосте соединение с внешним IPv4 `1.1.1.1:443` успешно; внутри того же профиля родительский и дочерний Python получают Windows 10013, native curl тоже не соединяется. Дочерний loopback echo проходит. Та же секция сетевой политики применена к дереву реальных движков 0.1.18 и финального 0.1.21. Глобальные firewall, proxy и сертификаты не менялись. [Документация сетевой политики MXC](https://github.com/microsoft/mxc/blob/main/docs/backends/process-container/networking.md).

Модели и среды скопированы исключительно в собственные тестовые каталоги на E: из уже имеющихся ресурсов; хеши файлов весов сверены с оригиналами. Повторной загрузки весов нет. После завершения деревьев временные копии и скачанный архив инструмента удалены с проверкой точных путей, собственного маркера и отсутствия reparse points: освобождено около 19,5 ГБ десятичных байтов. Хеши, журналы и извлечённый QA-инструмент сохранены; оригиналы и рабочая БД не изменялись. Тест использует автоматический выбор устройства; отдельно доказанным CUDA-профилем этот сетевой прогон не называется. Предыдущие отдельные CPU/CUDA-проверки сохраняют собственную область применимости.

### Native-устойчивость

Новые opt-in команды финального EXE: `--soak-self-test`, `--soak-check`, `--soak-candidate` и отдельные `--soak-live-check`/`--soak-live-candidate`. Обычный запуск их не выполняет. Все данные создаются в новом явно заданном каталоге. Звук, генерация моделей, автозапуск и обновления выключены.

Длительности: self-test 12 секунд; короткий прогон 1 200; длительный 86 400 секунд. Часы не ускорены. `QueryUnbiasedInterruptTime` исключает сон/гибернацию. Первая половина — запрос фонового маскота, вторая — открытые настройки с навигацией, сохранениями каждую минуту и minimize/restore каждые пять минут. Сохраняются CPU, private bytes, handles/GDI/User objects и реальные состояния видимости. Наблюдения пишутся потоком, не накапливаются в RAM. Итог появляется только после завершения backend и повторного чтения сохранённых настроек из БД.

Режим с управляемым окружением разрешает показ маскота на неактивном desktop и сохраняет настоящие часы. Live-режим использует реальные системные адаптеры, поэтому ограничения уведомлений неактивного desktop могут скрывать маскота; его нельзя назвать чистым замером видимого маскота. Обе области различаются в отчётах. Отдельного Explorer, взаимодействия с физическим вводом, активного compositor и screen reader эти тесты не создают. Интервал контрольного таймера в одну секунду не является измерением UI p95.

Два коротких прогона **завершены**: 1 200,425 / 1 200,429 секунд измерений после прогрева, оба дерева exit0, на каждом десять save-roundtrip и два minimize/restore. Компьютер: Ryzen 9 3900X, 24 логических CPU, около 64 ГБ RAM, Windows 11 Pro 26300. Знаменатель CPU — все 24 логических процессора, только основной UI/service-процесс; внешних ML-процессов здесь нет.

| Короткий native-режим | Память, пик | Средний CPU машины | Видимость |
|---|---|---|---|
| injected, фоновый маскот / настройки | 6,46 / 11,77 МиБ | 0,0093 / 0,0230% | Маскот 600/600 и 601/601 отсчётов; главное окно скрыто в первой половине |
| live adapters, фон / настройки | 9,95 / 11,86 МиБ | 0,0068 / 0,0194% | Неактивный desktop ограничивает уведомления: маскот скрыт, главное окно видимо |

Handles/GDI/User объекты не показали накопления за эти двадцать минут. Медиана private bytes между начальным/конечным окном открытых настроек выросла на 0,61/0,53 МиБ; короткий интервал не доказывает отсутствие длительного роста и не экстраполируется в утечку. Для этого запущены настоящие сутки.

Текущий суточный статус: **выполняется, ещё не завершён**. `native-24h-02` и `native-live-24h-02` реально работают в сохраняемых unified-exec sessions 85743/64451; проверены SHA и несколько последовательных обновлений progress. Первая попытка `*-24h-01` через Start-Process прервалась при выходе внешнего job и не засчитана. Настроен временный тихий thread heartbeat для разбора итогов и обновления документов, после итога он отключается. Питание и сон пользователя не меняются.

Короткие и суточные результаты фиксируются в `work/unattended-p5-p8-20261024/`; один запуск команды не считается прохождением 24 часов. При завершении необходимы оба итоговых JSON, фактические 86 400 секунд бодрствования, чистый выход дерева, анализ трендов ресурсов и проверка финальных настроек.
