# Восстановление основного окна после сворачивания

24 октября 2026. Кандидат 0.1.10; исправление интерфейса, без изменения формата данных, настроек, моделей и аудио.

Пользователь прислал снимок 0.1.9: большая часть основного окна прозрачна, остаются отдельные изменившиеся кнопки. Вероятный триггер со слов пользователя — сворачивание. Это отдельный дефект основного окна, не прежний срез края маскота.

## Что установлено и изменено

Закреплённый Winit backend Slint 1.18.1 по умолчанию создаёт прозрачные окна. Для основного окна теперь явно указан `with_transparent(false)`; маскот и сообщение сохраняют свою прозрачность. Software renderer показывает только повреждённые области из повторно используемого буфера. Если Windows потеряла клиентское содержимое, простой `request_redraw` может не вернуть неизменившийся фон.

При возврате основного окна из фона и после сворачивания/окклюзии очищается кэш частичного рендеринга и запрашивается новая полная отрисовка. Используется публичный `Window::take_snapshot`: у закреплённой версии software renderer он переключает repaint buffer type и очищает кэш; результат снимка не сохраняется и освобождается. Восстановление запускается один раз на переходе, после обработки новых размеров, а не каждый кадр/секунду. Это совместимость с конкретной закреплённой версией Slint; при её обновлении native regression обязателен. Ошибка восстановления сообщается в статусе, приложение не падает.

## Проверка и её границы

- Исходная версия в `restore-repaint-before-02` выдержала 20 сворачиваний и 50 возвратов: естественный пользовательский сбой в этой автоматической серии не воспроизвёлся. Его точный OS-триггер не объявляется установленным.
- Новый regression читает **уже показанные клиентские пиксели** собственного HWND через GetPixel. Снимок Slint для этой проверки не используется, поскольку сам очищает renderer cache и маскировал бы ошибку.
- Тест также намеренно очищает только поверхность своего процесса через PatBlt. Проверяет, что обычный запрос redraw оставляет контрольную точку пустой, затем возвращает окно через тот же путь Shell.open и требует восстановленного цвета фона в трёх точках. Это имитация потери поверхности, не заявление о точном воспроизведении события пользователя.
- Финальные debug и установленный release EXE прошли 20 сворачиваний, 50 возвратов, контроль с потерей поверхности, реальные трей/окна/выход и сохранение геометрии маскота. `GetPixel`/PatBlt QA helpers отказываются работать с окнами чужого PID. Desktop input не имитируется.
- 16 app + 3 platform теста прошли, один opt-in ML пропущен; Clippy `-D warnings` и fmt check прошли. ML/Python не менялись, повторная загрузка моделей не требовалась. Шесть исходных пользовательских изменений сохранены байт в байт.

Логи: `work/remaining-20261024/restore-repaint-tests-02.log`, `restore-repaint-clippy-03.log`, `restore-repaint-fmt.log`, `restore-repaint-final/evidence/result.json`, `restore-release-native/evidence/result.json`. Ранний промежуточный after-result неверно выводил число сворачиваний 0 из копии счётчика за пределами move-замыкания; финальный regression использует разделяемый счётчик и проверенно сообщает 20. Исторический файл не выдаётся за итоговый.
