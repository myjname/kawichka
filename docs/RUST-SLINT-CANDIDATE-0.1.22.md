## Исправление и native-проверка доступности

Настоящий Windows UI Automation-клиент обнаружил в 0.1.21 безымянное readonly-поле описания обновления. На странице «Помощь и обновления» screen reader не получал его назначения. Единственная правка product source — `accessible-label` этого `TextEdit`: «Описание обновления» / «Release notes». Работа данных/генерации/расписания не менялась.

Кандидат **0.1.22** собран и проверен через настоящий UIA-provider Slint/AccessKit на двух собственных неактивных desktop:

| Конфигурация | Результат |
|---|---|
| Русский, тёмная тема | Все восемь разделов переключены через InvokePattern; безымянных экспонированных элементов управления нет |
| Английский, светлая тема | Те же восемь разделов и отсутствие безымянных элементов подтверждены |
| Исправленное поле | Локализованное имя найдено; ValuePattern сообщает `IsReadOnly=true` |
| Выход | В обеих конфигурациях UIA-действие «Выйти из приложения» завершило именно тестовый процесс с кодом 0 |
| Безопасность стенда | Синтетические отдельные БД, desktop не стал input desktop; физический ввод не отправлялся |

Проверены также имена элементов, находящихся за границей viewport, а не только текущей видимой части. При переходе должны измениться наборы контролов; совпадающее содержимое восьми страниц не считалось бы успешной навигацией. Исследовательская первая попытка выбрала окно маскота и не засчитана; успешный стенд выбирает главное окно по его размеру.

Это автоматическая проверка деревьев, имён, навигационных InvokePattern и штатного выхода. Полный keyboard/focus/ScrollIntoView, физический DPI, активный compositor, все динамические диалоги и практический Narrator **не проверены**. Чистая Windows не создавалась.

## Семь партий настоящей текстовой модели

Финальный **упакованный worker 0.1.21**, уже имеющиеся Gemma 4 12B и readonly-компоненты создали **7 × 13 = 91** русскую фразу с общей историей. Это новые синтетические партии с публичным стандартным характером; пользовательские тексты/пресеты/живая БД не читались. Модели не устанавливались и не скачивались. Выбран `tts_model=system`, поэтому этот путь worker выдаёт только текст: аудио не создавалось и не проигрывалось.

- 63 первичные и 28 повторных реплик.
- Категории: 7 завтраков, 7 обедов, 7 ужинов, 35 перерывов и 35 разминок.
- После каждой партии вся история передавалась следующей; в пределах партии worker обновлял recent history штатным способом.
- Все 91 приняты, прерываний нет; модель выполнила 69 дополнительных попыток после отбраковки кандидатов. Общее время — **923,015 с**, около 15 минут 23 секунд. Каждую партию движок загружал/освобождал штатно.
- Производственная защита и отдельный анализ результатов не нашли нормализованных точных дублей, совпадающих шаблонов с заменой названия еды, одинаковых первых трёх слов среди последних восьми реплик и начала «Пора».

Это проверка **семи партий**, а не семи реальных дней, полуночи, расписания Rust или всего дневного workflow с аудио. Тексты остались в приватном ignored `work/`. Субъективная интересность и отсутствие любых смысловых повторов не объявляются доказанными. Есть измеримый стилистический перекос: 22 из 91 начинаются словом «Твои»; суммарно «Ты/Твой/Твоя/Твои» — 50 из 91. Поэтому успешную защиту от дублей нельзя выдавать за завершённую оценку характера и разнообразия всех конструкций.

## Лицензии выбранной среды

Прочитаны метаданные **131 дистрибутива**: 94 в базовом Python и 37 в Cosy-слое. Это число записей по слоям, включая разные версии одинаковых проектов. **251** локальный файл LICENSE/COPYING/NOTICE/AUTHORS сверён с SHA-256 из wheel RECORD, несовпадений нет. Пакеты не импортировались и установленная среда не менялась.

У шести дистрибутивов локального текста не было. Для двух tokenizers текст извлечён без выполнения из исходных архивов точной версии PyPI, весь архив сверен по опубликованному SHA. Для остальных четырёх взяты официальные исходники с закреплённым commit соответствующего тега. Дополнительно найден основной текст llama.cpp по b11719; установленный архив содержал отдельный LLVM/OpenMP notice, но не основной LICENSE.

[Реестр источников и сохранённые тексты](RUST-SLINT-DEPENDENCY-NOTICES.md). Это закрывает сбор и проверку наличия текстов для обследованной среды; не является правовым разрешением распространять любой состав. Полные модельные условия, CUDA/прочие native redistributables и остальные конфигурации отдельно не квалифицированы. Python/llama/веса не входят в installer 0.1.22: они используются либо устанавливаются отдельно по выбору пользователя. Документальные дополнения не меняют установленную среду и не маскируются под содержимое исходных wheels.

## Суточные прогоны и неизменность

`native-24h-02` / `native-live-24h-02` продолжаются **на прежнем неизменённом EXE 0.1.21**, без перезапуска. На момент этой итерации они отработали более 45 минут бодрствования, ошибок не записано. Это ещё не сутки. Временный heartbeat остаётся настроенным для разбора фактических итогов и сам отключится после завершения.

Исходный `source-021.json` сохранён; `source-022.json` и `source-delta-021-022.json` показывают ровно одно изменение product source — UIA-имя поля в app.slint, остальные 185 входов не изменены. Девять прежних изменённых tracked-файлов сохранены побайтно. Helper проверки исторических свидетельств исправлен: он больше не переписывает старый source snapshot при последующих проверках.

Суточный результат нельзя автоматически приписать другому SHA 0.1.22. Он относится к ядру/service/Shell конкретного 0.1.21. Для 0.1.22 отдельные свидетельства — release build, native UIA и контроль целостности артефактов. Повторять все ML/данные тесты из-за доступного имени не потребовалось: backend и логика данных не изменились. Прежние 147 passed / 9 ignored сохраняют свою привязку к 0.1.21.
