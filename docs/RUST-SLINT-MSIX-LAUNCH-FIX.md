# Исправление запуска 0.1.28 из Проводника

25 октября 2026. Пользователь воспроизвёл отказ установленного `Kavychka.exe` при двойном клике. Ошибка launcher: `Installed data is unavailable; reconnect its disk or restore a profile. No empty library was created.` Повторный запуск проверяющим процессом работал; первоначальное предположение о временном отказе не подтвердилось.

## Установленная причина

Одинаковый логический путь `%LOCALAPPDATA%/Kavychka/.kavychka-next` соответствовал разным физическим данным. Новая папка при запуске установщика из MSIX Codex была создана в `%LOCALAPPDATA%/Packages/<Codex package>/LocalCache/Local/Kavychka/.kavychka-next`. Процессы проверяющего окружения видели эту виртуальную копию. Обычный Explorer видел общую папку и прежнюю библиотеку, но новая подпапка в ней отсутствовала.

Подтверждение: один и тот же собственный Rust probe, одинаковые аргументы, пользователь, integrity level и отображаемые переменные окружения. Проверены `metadata`, чтение маркера и `GetFinalPathNameByHandleW`. В процессе, запущенном существующим Explorer, новая подпапка возвращала Windows error 2, файлы — error 3. Проверяющий процесс возвращал физический путь в кеше пакета Codex. Обычный новый объект `Shell.Application.ShellExecute` в этом окружении не обеспечил независимого контекста; воспроизводящий запуск выполнен через `Document.Application.ShellExecute` уже открытого окна Explorer.

Это ошибка способа установки и её приёмки. Предыдущие SHA/CI, тесты на явных путях внутри workspace и проверка копирования данных остаются действительными. Предыдущий успешный запуск из контекста проверяющего процесса **не доказывал обычный пользовательский запуск**.

## Исправление и проверка

- Из обычного, непакетированного процесса скопирован текущий профиль с уже завершённым мастером в предназначенную общую папку. Прежняя legacy-библиотека и пути моделей не изменялись.
- Перед публикацией проверены 78 файлов данных по SHA-256, SQLite integrity, все 51 запись и настройки завершённого русского мастера. Служебный process lock создан заново. Исходный виртуальный профиль сохранён рядом под резервным именем, чтобы последующие чтения логического пути не попадали в старую копию.
- Одна неудачная промежуточная папка удалена только после проверки точного пути и совпадения всех файлов с сохранённым резервом. Исходные данные и резерв не удалены.
- После исправления `GetFinalPathNameByHandleW` в обоих контекстах вернул одну обычную общую папку. Запуск тем же существующим Explorer успешно создал установленный `app.exe`, без новой записи ошибки. Мастер завершён, язык русский.
- Из обычного процесса подтверждена доступность выбранных весов Gemma и CosyVoice, а также Python. Это проверка наличия файлов, не новый полный ML-прогон.
- Установленные исполняемые файлы не менялись, версия **0.1.28**, SHA `app.exe` по-прежнему `f9201668a2eca1edd8e97fc8fd131068b102a60b8fd93d39e77978fd3012a6e2`. Модели не скачивались повторно, значения настроек не сбрасывались.

Частные свидетельства: [результат переноса](../work/launch-fix-028-20261025/repair-result.json), [обычный запуск после исправления](../work/launch-fix-028-20261025/normal-launch-after.json), [ресурсы обычного процесса](../work/launch-fix-028-20261025/normal-resources.json). Полные пути и резерв находятся в этих локальных игнорируемых файлах; в публичные артефакты профиль не включается.

## Правило дальнейшей приёмки

**Предотвращение повторения, 27 октября:** [кандидат 0.1.29](RUST-SLINT-INSTALLER-DEPENDENCIES-20261027.md) добавляет проверку реального пути автоматически удаляемой пробы в корнях AppData и родителе назначения, запрет явного package LocalCache и отказ до открытия/изменения профиля. Проверены как новая, так и существующая папка: одной проверки package identity или пробного файла внутри существующей папки недостаточно. Обычный Explorer и три отрицательных сценария из Codex подтверждены на одном окончательном SHA Setup. Рабочий установленный бинарник остаётся 0.1.28; новый Setup не опубликован и не установлен поверх него.

Проверки установленного пользовательского экземпляра, выполненные из MSIX-хоста, должны подтверждать физические пути и обычный Windows-контекст запуска. `require_escalated`, одинаковый SID и успешный `is_file` сами по себе этого не устанавливают. Не лечить такую разницу сбросом профиля, широкими изменениями ACL, отключением виртуализации Windows или постоянной привязкой приложения к кешу Codex.

Суточные, аппаратные, Narrator и прочие открытые условия P4–P8 самим исправлением не закрываются. Обычный запуск после исправления проверен агентом. **27 октября пользователь подтвердил группы 1–13 ручного чек-листа**, включая обычное открытие, восстановление, настройки и автозапуск: [ручная приёмка](RUST-SLINT-MANUAL-ACCEPTANCE-20261027.md). Прежнее ожидание пользовательского подтверждения снято.
