## GUI-проверка

На двух независимых синтетических профилях запущен байт-в-байт опубликованный launcher Portable.exe 0.1.30 (alias Kavychka.exe для allowlist существующего QA runner). Затем проверен настоящий GUI-вход скачанного установщика с KAVYCHKA_APPLY_UPDATE=1, обычным/каноническим portable root и обратной формой program. Исходные указатели старого launcher не переписывались для обхода проверки. В обоих случаях установка завершилась exit 0, версия стала 0.1.34, настройки, две строки фраз, аудио и тестовый пресет сохранились; откат вернул 0.1.30 с теми же данными, SQLite integrity ok.

Тесты выполнены из настоящего Explorer-контекста после подтверждения физического AppData-файла, на отдельных НЕактивных desktop. Экран не переключался, ввод не отправлялся, Computer Use не использовался. GUI сам выполнил штатные install/open callbacks; дочерние процессы принадлежали QA job и останавливались после выхода установщика. Это не физическая приёмка нового главного окна или аудио и не автоматическое нажатие кнопок старого обновлятора.

Первые GUI-попытки из Codex были некорректным стендом: require_unpacked дополнительно проверяет физические AppData-записи даже для portable, а унаследованный контекст их перенаправлял. Их таймауты не засчитываются как доказательство конкретной продуктовой ошибки. Для окончательного прогона проверен обычный физический AppData; защита не обходилась. Ошибка GUI 0.1.31 подтверждена пользовательским скрином и его сохранным профилем; второе сырое сравнение отдельно воспроизведено CLI на кандидате 0.1.32. Кандидат 0.1.33 был остановлен настоящей CI-регрессией отката. Кандидаты 0.1.32/0.1.33 не публиковались, их теги не передвигались.

Частные свидетельства: `work/publish-20261028-034/gui-qualified.json`, `ordinary-context.json`, `ordinary-exit.json`, `published.json`, `download/release-evidence-ordinary.json`. Синтетические результаты GUI и журналы перечислены внутри gui-qualified. Частные данные и пресеты в релиз/Git не включены.
