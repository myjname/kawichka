# Совместимое обновление inference-зависимостей, 27 октября 2026

## Результат и границы

В локальном кандидате **0.1.30** устранён конфликт Pillow/Gradio и обновлён согласованный набор Torch/Transformers. Рабочая 0.1.28, пользовательские среды, настройки, модели и записи не заменялись. Коммита, push и публикации нет. Отложенная аппаратная приёмка не проводилась; эта работа не закрывает P4–P8 целиком.

CUDA-набор использует 12.6; проверка доступности в приложении соответствует набору. Это не подтверждение всех драйверов и видеокарт.

## Корректная Qwen-сборка

[Upstream Qwen 0.1.1](https://github.com/QwenLM/Qwen3-TTS/blob/main/pyproject.toml) закрепляет старые Transformers/Accelerate и включает Gradio; доступная Gradio требует Pillow<13. Простая замена pins оставляла бы неверные метаданные. Теперь приложение собирает отдельный wheel с собственным именем и корректными зависимостями: inference-код Qwen без demo/CLI и Gradio. Это не установка upstream через `--no-deps`.

Источник закреплён SHA-256 `11a290d8dabc7ef91a90c54478c8ab19b3edb1d85c0882313721892bdc4af15d`; builder проверяет точный исходный текст перед адаптацией. Apache license, исходная атрибуция, собственный NOTICE и RECORD сохранены. Детерминированный итоговый SHA хранится в `assets/components.json`; wheel из исходников и из Setup одинаковый.

Адаптация к HF5 затрагивает декораторы, causal mask/cache_position и unscaled RoPE. Существенная проверка выявила, что прежняя инициализация Qwen могла перезаписывать уже загруженные веса и оставлять непостоянные RoPE-буферы пустыми. Исправлено через HF-инициализацию с защитой loaded parameters и явным восстановлением математических RoPE-буферов. Глобальных monkeypatch Transformers нет. Промежуточные post1/post2 с непустыми WAV **не признаны совместимыми**; итоговые свидетельства относятся к post3.

## Установка и обратная совместимость

Установка проверяет `pip check`, точные версии, защиту загруженных весов и RoPE до readiness marker. Новый `runtime_profile` отличает квалифицированную среду от старой; веса повторно не скачиваются из-за смены профиля. Пользовательская среда обновляется штатной явной установкой компонентов; здесь она не запускалась.

CosyVoice устанавливается в staging-layer и публикуется после проверки импорта. Сохранены исходная Cosy-ревизия и размещение Transformers в Cosy/site для совместимости с 0.1.28. При ошибке публикации прежний слой восстанавливается. Очистка ограничена собственными помеченными staging-каталогами без ссылок. Внешняя Python-среда не используется для pip.

При подтверждённой ошибке системного CA GitHub/codeload повторяется через актуальный Certifi: TLS и hostname verification остаются включены. Другие ошибки не вызывают fallback.

Старый загрузчик имеет фиксированный список backend-файлов. Первый кандидат не прошёл rollback из-за новых имён. Итоговый `candidate-02` сохраняет формат: два небольших новых source-модуля читаемо встраиваются при упаковке в существующие Python entrypoints. Скрытого исполняемого asset и замены стабильного загрузчика нет. Обычный SQLite health check сохранён.

## Проверки

Локальные свидетельства находятся в [work/dependency-upgrade-20261027](../work/dependency-upgrade-20261027/) и не включены в Setup.

- **143 Python-теста**, **174 Rust-теста**, 9 намеренно ignored; Clippy workspace/all-targets `-D warnings` прошёл. Первый Python-прогон в ограниченной песочнице не смог корректно запустить/убрать loopback fixture; обычный разрешённый прогон прошёл все 143. Отказ песочницы не учитывается как passed.
- Штатный Components-installer проверен в отдельных QA-папках: CPU установлен с нуля сразу с post3, GPU начат с пустой среды и затем обновлён штатным установщиком до итогового post3, включая staged Cosy. CPU и эффективный Cosy-layer прошли `pip check`. Упакованный health check подтвердил версии и защиту инициализации.
- CPU Qwen 0.6B, одинаковые reference/seed/greedy-настройки: до/после обновления совпали **21×16 codec-токенов**, обе записи содержат **40320 samples / 24000 Hz**, максимальная разница waveform **5.51343×10⁻⁷**. Это одна контрольная фраза, не исчерпывающее равенство моделей.
- GPU с производственными defaults: Qwen 0.6B и 1.7B дали конечные записи по 3.04 секунды с естественным EOS; **974 / 976 checkpoint-тензоров** сверены с загруженными весами с учётом рабочего dtype. CosyVoice3 дал валидную запись 11.2 секунды. Референс публичный default-en.wav, текст русский; воспроизведения и доступа к рабочей SQLite не было. Скорость — разовое наблюдение на данном ПК.
- Реальный Setup **0.1.28 → 0.1.30 → rollback** сохранил шесть исходных строк, настройки и медиа, отдельно сохранил правки после обновления. SHA старого root-launcher не изменился. Модели и глобальная интеграция не переносились.
- Упакованный Slint/service regression и normal SQLite health check пройдены. Упакованный builder воспроизводит ожидаемый wheel SHA.
- Старое приложение 0.1.28 с новой GPU-средой прошло сквозной Gemma→Cosy-сценарий: три записи созданы/декодированы, отмена за 541 мс. Безоконный software-render p95 во время ML 9.95 мс, максимум 24.59 мс, кадров >100 мс нет. Это функциональная проверка обратной совместимости и ограниченный UI probe, не native compositor/hardware-приёмка.
- Финальный упакованный 0.1.30 с новой GPU-средой: три записи созданы/декодированы, отмена за **515 мс**, software-render p95 во время ML **9.9045 мс**, максимум **44.8161 мс**, кадров >100 мс нет. Обе тестовые SQLite прошли `integrity_check`; рабочая база не открывалась. Это не суточная проверка и не приёмка на целевом ноутбуке.
