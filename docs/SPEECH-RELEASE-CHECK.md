# Проверка разборчивости озвучки перед выпуском

Созданный, ненулевой и успешно декодируемый WAV/FLAC ещё не доказывает, что произнесён заданный текст. В 0.1.38 такая проверка пропустила неразборчивый результат CosyVoice. Для приёмки нейронной озвучки нужны оба уровня ниже.

## Обязательные проверки

1. В CI запустить `tests/test_cosy_attention.py`: маленькая случайная Qwen-модель, без скачивания весов, сравнивает пошаговое выполнение с полным проходом. Старое поведение должно воспроизводить потерю контекста, исправленное — совпадать с полным проходом. Также проверяются prefill, готовая полная маска, legacy cache и некорректный размер маски.
2. `tests/test_speech_cache.py` подтверждает, что переозвучка не подхватит старый повреждённый кеш, новый результат повторно используется для того же запроса, а исходные файлы не удаляются.
3. До публикации stable сгенерировать реальные записи компонентами **точного скачанного CI-пакета**, используя существующие проверенные модели в отдельном тестовом каталоге. Для CosyVoice проверить CPU и CUDA, русский и английский, минимум два референса/подачи. Не подменять эту проверку тестом успешного завершения процесса или ненулевой амплитуды.
4. Прогнать `next/tools/verify_speech.py` на этих записях. Проверка работает локально, не отправляет записи в сеть, не воспроизводит звук и не меняет профиль приложения. Веса Whisper base — отдельный инструмент разработчика; в приложение и установщик они не входят.
5. Проверить отрицательный контроль: прежняя повреждённая запись должна дать `passed: false` и код выхода 1. Иначе положительным результатам проверки доверять нельзя.

## Вход и запуск

Файл cases JSON содержит массив объектов с полями `audio` (абсолютный путь), `text` (ожидаемая фраза), `language` (`ru`/`en`). Например:

```json
[{"audio":"E:/qa/example.wav","text":"Встань и немного разомнись. Пять минут я подожду.","language":"ru"}]
```

Из корня проекта, встроенным Python подготовленной среды моделей:

```powershell
& $python -B next/tools/verify_speech.py --cases $cases --components $components --asr-model $whisperBase --output $newReport
```

Переменные должны указывать на реальные тестовые пути. `$components` содержит проверенные `cosy/Whisper` и `cosy/site`. `$whisperBase` — официальный checkpoint Whisper base с SHA256 `ed3a0b6b1c0edf879ad9b11b1af5a0e6ab5db9205f891f668f8b0e6c6326e34e`; инструмент проверяет хеш до загрузки. Файл отчёта должен быть новым. Автоматических скачиваний нет.

## Оценка результата

По умолчанию принимается character error rate не выше 0.35, при нормализации регистра, пунктуации и ё/е. Это допускает небольшие ошибки самой ASR-модели и выявляет существенные пропуски, бессвязные слоги и повторяющееся бормотание. Пробная ожидаемая фраза не подаётся распознавателю как подсказка. Тишина/нечисловые значения/слишком короткий файл не являются успешной озвучкой.

Не повышать порог ради неудачного прогона. Исследовать причину и сохранить отрицательные результаты. ASR не подтверждает естественность, тембр, отсутствие любых шумов или субъективное сходство с голосовым пресетом — эти свойства остаются отдельной оценкой прослушивания.

В итоговом отчёте указывать commit/tag, SHA256 установщика, устройства CPU/CUDA, число и языки примеров, максимальную ошибку и результат отрицательного контроля. Личные референсы, транскрипции, записи и подробные локальные отчёты не прикладывать к публичному релизу и не добавлять в Git. Для повторяемости сохранять их в исключённом тестовом каталоге. Без положительной квалификации реальной речи выпуск не объявляется проверенным по качеству озвучки.
