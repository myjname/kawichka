# Кавычка Next

Предварительный выпуск — **0.1.30**: защита от установки профиля в MSIX-кеш, согласованное обновление Torch/Transformers/Pillow и inference-сборка Qwen без конфликта Gradio. [Проверки зависимостей](../docs/RUST-SLINT-DEPENDENCY-UPGRADE-20261027.md), [пользовательская приёмка 0.1.28 и отложенное оборудование](../docs/RUST-SLINT-MANUAL-ACCEPTANCE-20261027.md). Настройки, записи и пути моделей сохраняются при обновлении; совместимую новую среду можно явно установить в разделе моделей без повторного скачивания весов. Исторические документы не означают, что P4–P8 или стабильный публичный выпуск уже приняты.

Отдельная версия на Rust + Slint. Основной WinForms-проект сохранён; действующая установка автоматически не переключается. Для проверки подготовлен локальный установочный кандидат, ещё не публичный стабильный выпуск.

## Установка готового кандидата

Открой Kavychka-Next-Setup.exe. Установка выполняется для текущего пользователя без администратора. Можно выбрать папку программы и общее хранилище; прежняя библиотека определяется автоматически или указывается отдельно. При первом переходе старая библиотека копируется в подпапку .kavychka-next общего хранилища; исходные данные сохраняются, модели и совместимые среды используются по прежним путям. Закрой старую Кавычку перед переносом.

При обычном обновлении папка данных сохраняется: ничего вручную переносить и повторно скачивать не требуется. В настройках установленной версии есть проверка обновлений, загрузка и явный перезапуск. Канал GitHub: стабильные теги next-vX.Y.Z с файлом Kavychka-Next-Setup.exe и SHA-256 GitHub. Пока такие релизы не опубликованы, проверка не найдёт новую Rust-версию.

Базовый режим не требует Python, CUDA или моделей. В разделе моделей выбери текст, голос и устройство Auto/CPU/NVIDIA CUDA, затем установи выбранное. Каталог целиком не скачивается. Новые среды и веса хранятся в components внутри рабочей библиотеки. Большая чистая установка CUDA/CosyVoice отдельно требует нескольких гигабайт; её проверка на чистом пользовательском ПК ещё открыта.

Характер, голос и внешность выбираются независимо. Раздел «Характер» импортирует/экспортирует .kavychka, редактирует описание и расшифровки, принимает готовые изображения/атласы и голосовые референсы. Личные пресеты хранятся локально.

В текущих исходниках P5 раздел «Хранилище» позволяет выбрать операцию: экспорт профиля, восстановление или перенос общей папки. Для ZIP выбираются библиотека/история и аудио, затем рассчитывается состав; модели и среды в профиль не входят. Восстановление сначала показывает сводку, затем создаёт проверенный резерв и применяется явно. В непустой библиотеке текущие настройки и исключения сохраняются. На чистой установке профиль можно восстановить прямо на первом экране мастера. Лимит резервов текущего хранилища сохраняется.

Перенос общей папки доступен установленной версии: новая отдельная папка, оценка объёма по категориям и пика, перезапуск в окно копирования с отменой. Свои модели/среды копируются без скачивания, внешние пути остаются на месте, исходная папка сохраняется. Предпросмотр из исходников поддерживает профиль; он не переносит произвольные внешние модели как собственный common. [Приёмка и точные ограничения P5](../docs/RUST-SLINT-P5-ACCEPTANCE.md): настоящий файловый ENOSPC ещё требует отдельного административного прогона; физические проверки P4 открыты. Ранее собранный installer в outputs не обновляется от изменения исходников: его нужно пересобрать отдельно, полная квалификация пакета — P7.

Обновление сначала проверяет пакет, сохраняет резерв данных без весов и запускает новую программу для проверки. Доступен откат в течение 7 дней; изменения после обновления сохраняются отдельной копией для разбора, а не сливаются автоматически. Лимит резервов/карантина по умолчанию 2 ГБ и меняется в настройках/установщике. Последняя пригодная копия молча не удаляется. Деинсталлятор в этот кандидат не входит.

Подробности и фактические проверки: [отчёт переноса и установки](../docs/RUST-SLINT-MIGRATION-INSTALL-UPDATES.md).

## Сборка и проверки

Нужны Rust с toolchain MSVC и средства сборки C++ для Windows. Cargo.lock фиксируется в проекте. Модели для этих проверок не нужны.

Из корня проекта в PowerShell:

```powershell
.\next\dev.ps1 -Action test
.\next\dev.ps1 -Action clippy
.\next\dev.ps1 -Action build
```

Скрипт направляет кеш и сборку в игнорируемую work на диске проекта, если CARGO_HOME не задан заранее. При заполненном кеше доступен параметр -Offline. Первая сборка требует загрузки зависимостей Rust; это не загрузка пользовательских моделей. Форматирование проверяется через -Action fmt.

При автоматической проверке пользовательской установки из MSIX-хоста нужно отдельно проверить физический путь профиля и запуск обычным Explorer: одинаковый логический LocalAppData не гарантирует одинаковые файлы. [Подтверждённый случай и методика проверки](../docs/RUST-SLINT-MSIX-LAUNCH-FIX.md).

Нынешний START.bat запускает WinForms-версию. Для исходников новой оболочки предусмотрен отдельный запуск ниже. После установки готового кандидата используется его Kavychka.exe или ярлык «Кавычка».

## Рабочее окно Slint

Из корня проекта:

```powershell
.\next\Start-preview.ps1
```

Можно также дважды нажать next/Start-preview.bat. Уже собранный исполняемый файл используется при совпадении хешей исходников и программы: повторный запуск не требует пересборки или повторного скачивания зависимостей. После изменения исходников скрипт выполняет cargo build. На чистом клоне Git без сборки нужны Rust и C++ Build Tools.

Скрипт собирает kavychka-app и открывает его с отдельными данными в work/slint-library-user-preview. При первом запуске находит прежнее хранилище через Kavychka-storage.json в LocalAppData либо стандартную папку Kavychka и создаёт проверенную рабочую копию настроек, библиотеки и пресетов. Перед первым импортом закройте старую «Кавычку». Источник можно указать явно: -LegacySource "E:\MyLibrary". Исходные файлы и общий указатель не изменяются; веса и установленные среды используются по исходным путям без копирования. Последующие изменения старого приложения автоматически не синхронизируются.

Базовые напоминания, встроенные фразы, системный голос и прослушивание готового FLAC работают без Python и моделей. Генерация новых текстов, нейроозвучка и ZIP-экспорт используют отдельный процесс существующей Python-среды. При готовом кеше Rust можно добавить -Offline. Диагностика каждого запуска находится в отдельной work/slint-shell-launch-*.

Работают маскот, сообщение, настоящий трей, расписание, подтверждения и повторы по активности мыши/клавиатуры. Закрытие настроек оставляет приложение работать; пункт «Выйти» завершает его. Двойной клик по маскоту или клик по значку трея открывает настройки. Маскота можно перетаскивать и скрывать; в трее остаётся управление. Поверх полного экрана изображение и звук настраиваются отдельно.

Есть паузы на заданное время и до завтра, таймер у маскота, ручная разминка и отметка завтрака каждый день. Таймер разминки стартует после отметки завтрака, включая выходные; отдельный повторный клик не перезапускает его. По умолчанию кнопка подтверждения скрывает перерыв, а достаточный отдых прекращает повторы. Повторы используют три разные встроенные дразнящие фразы; последняя шутка не выключает приложение.

Базовый звук — сигнал, затем установленный голос Windows выбранного языка. Если голоса нет, остаются текст и сигнал с объяснением. Режимы звука, повторов, темы и RU/EN настраиваются. Запись SQLite выполняется отдельным потоком до выдачи сообщения; короткий перезапуск восстанавливает текст без повторного сигнала. Просмотр неподтверждённых сообщений не подтверждает их автоматически.

В библиотеке работают отбор, прослушивание, подготовка дня, ручная генерация, переозвучка без изменения текста, отмена и ZIP с фразами/аудио. В разделе моделей раздельно выбираются текст и голос; весь каталог сразу не скачивается. Подхватываются прежние описание персонажа, голосовой профиль и подачи. Перенос состояния напоминаний, часового пояса и независимых пресетов описан в [текущем отчёте](../docs/RUST-SLINT-MIGRATION-INSTALL-UPDATES.md); [предыдущий отчёт о моделях](../docs/RUST-SLINT-MODELS-LIBRARY.md) сохраняет историю проверок.

## Сборка установщика и проверка перехода

```powershell
.\next\Build-package.ps1 -Version 0.1.0
```

Создаётся outputs/next/0.1.0/Kavychka-Next-Setup.exe. Сборка фиксирует версию в программе, использует статическую CRT, проверяет список комплектных файлов и отказывается выпускать пакет, если исходники менялись во время сборки. Повторно используй новый Output: существующий EXE не перезаписывается.

Для проверки двух разных собранных версий на отдельной копии:

```powershell
python -B next/tools/verify_install.py --setup <первый-setup.exe> --update <новый-setup.exe> --legacy-source <прежнее-хранилище>
```

Проверка пишет только новую папку work, проходит установку, обновление и откат, сравнивает настройки, строки и хеши медиа. Не меняет реальные ярлыки/автозапуск. Параметр --real-models дополнительно включает настоящую генерацию, прослушивание и управление библиотекой через установленное приложение; нужны рабочие модели и интерактивная Windows. Журналы и снимки этой проверки личные и не входят в Git.

Реальные установленные модели и библиотеку можно проверить отдельно (создаётся новая личная тестовая копия; запускается генерация и звук):

```powershell
.\next\Verify-models.ps1 -Source "E:\MyLibrary" -Offline
```

Путь условный. Нужны совместимые установленные модели/среды, закрытая старая программа и интерактивная Windows-сессия. Проверка не загружает веса. Её снимки содержат личные данные и остаются в игнорируемой work.

Проверка самого сценария запуска, настоящего окна Windows и закрытия на синтетических данных:

```powershell
.\next\Start-preview.ps1 -Offline -Verify
```

Проверка создаёт отдельные каталоги runtime и live в новой work/slint-shell-launch-*: управляемое время и настоящие окна/трей, 50 повторных открытий, WM_CLOSE, перезапуск, отказ запуска и производственное напоминание по системным часам. Каждый каталог содержит evidence/result.json и снимки. Все тестовые экземпляры сами закрываются. Обычное хранилище preview не используется.

Дополнительно проверить SAPI, короткий сигнал WASAPI и отмену звука можно через -Verify -VerifyAudio. Для нативной проверки нужна интерактивная Windows-сессия с работающим Explorer. Ограниченная среда Codex отклоняет Shell_NotifyIcon; это не повод пропускать проверку или считать значок работающим. Аппаратное отключение наушников, полная матрица DPI/доступности и суточная работа остаются самостоятельными проверками.

Полный отчёт этого этапа: [маскот, трей и напоминания](../docs/RUST-SLINT-COMPANION-REMINDERS.md).

Отдельная проверка событий Slint в памяти:

```powershell
.\work\rust-next-target\debug\kavychka-app.exe --data-dir "E:\TestData\EmptyShell" --smoke-test "E:\TestData\NewShellEvidence"
```

Оба пути условные, абсолютные; данные должны быть пустыми, каталог свидетельств — новым. Доступ к существующему непустому каталогу без специальной метки песочницы отклоняется. Прямой обычный запуск также требует --data-dir; скрытого выбора общей папки нет.

## Обслуживание кандидата

В «Помощь и обновления» доступны предварительный просмотр и локальное сохранение диагностики. Отчёт содержит только разрешённые счётчики, версии и причины с действиями; имена, тексты, описания персонажей, референсы, пути и исходные журналы не включаются. Ничего автоматически не отправляется.

Кнопка удаления сначала закрывает Кавычку, затем открывает отдельное окно со сводкой и подтверждением. Обычное удаление сохраняет данные, модели и указатель для переустановки. Полное дополнительно удаляет собственное общее хранилище и резервы; требуется корректный маркер владельца. Внешние пути сохраняются. При изменении состава после просмотра требуется повторная проверка. Полное удаление необратимо: заранее экспортируй профиль. В portable вместо этого закрывают приложение и удаляют всю распакованную папку.

Portable собирается из того же проверяемого установщика:

```powershell
.\next\Build-portable.ps1 -Setup .\outputs\next\0.1.2\Kavychka-Next-Setup.exe -Output .\outputs\next\0.1.2\Kavychka-Next-Portable.zip
```

Распакуй ZIP в отдельную папку и запусти `Portable.exe`. Программа и данные находятся в `program/` и `data/`; системные указатели, ярлыки и автозапуск не регистрируются. Переносить нужно всю папку при закрытом приложении. Внутренние пути подхватываются автоматически, внешние папки моделей остаются внешними. Прерывание переноса файлов средствами проводника не является транзакцией Кавычки: сохраняй исходную папку до успешного запуска копии. Обновление/откат используют тот же формат пакета; перенос общего хранилища отдельной кнопкой для portable отключён.

На чистой установке генерация по умолчанию встроенная, голос системный. При включении локального текста начальный выбор — Qwen 3.5 4B GGUF; это не скачивает модель автоматически и не меняет перенесённый явный выбор. «Установить или проверить выбранные» проверяет SHA файлов; повреждённые внешние веса не перезаписываются, исправленная копия устанавливается в собственное хранилище. Отмена запрашивается между стадиями и ограничена трёхсекундным ожиданием зависшего дочернего процесса; уже принятые тексты остаются в истории.

В дополнительных настройках моделей есть явное восстановление среды. Оно устанавливает служебные компоненты в `components/`, сохраняя внешнюю среду. Повреждённый управляемый Python сохраняется рядом как `runtime-unverified-*`; эти копии не удаляются автоматически и занимают место до отдельной очистки. Восстановление может заново скачать среду. Предварительная проверка свободного места учитывает колёса, распаковку и временный пик, а не только конечный размер. Ориентир RAM в списке — эвристика приложения (размер файлов + запас 2 ГБ для GGUF / 4 ГБ для Transformers и голоса, отдельно ОС); это не измеренный минимум, не гарантия скорости и не замена целевой аппаратной проверке. VRAM зависит от движка и размещения слоёв.

Сборщик включает инвентарь активных normal/build Cargo-зависимостей Windows и оригиналы уведомлений с проверяемым происхождением; отсутствие текста лицензии останавливает упаковку. Подробности и команда проверки — в `THIRD_PARTY_NOTICES.md`. Неподписанный локальный кандидат не является обещанием SmartScreen или завершённым лицензионным аудитом. GitHub workflow сохраняет installer/portable как артефакт проверки, не публикует release. Реальный канал выпуска квалифицируется отдельно.

### Консоль разработки

После сборки:

```powershell
.\work\rust-next-target\debug\kavychka-next.exe --help
.\work\rust-next-target\debug\kavychka-next.exe check-source --source "E:\TestData\LegacyCopy"
.\work\rust-next-target\debug\kavychka-next.exe preview-import --source "E:\TestData\LegacyCopy" --destination "E:\TestData\RustPreview"
```

Пути в примере условные. Для испытаний используйте копию данных. Назначение должно быть отдельным и пустым либо принадлежать той же незавершённой пробной операции. Модели не копируются; путь активного хранилища не переключается. Успешный повторный импорт не создаёт дополнительные строки. Изменившийся источник требует нового назначения.

Для preview-import старая «Кавычка» должна быть закрыта: инструмент получает её прежний mutex и не завершает её принудительно. Ввод/вывод источника дополнительно блокирует одновременную запись во время чтения. Ctrl+C отменяет работу с сохранением журнала для повтора.

Начальный лимит — 2 000 000 000 байт; изменить можно через --max-bytes. Проверяется также свободное место для промежуточного захвата, SQLite backup и VACUUM. Пробная копия не является автоматически активированной новой версией или полноценным архивом отката.

Вывод консоли содержит счётчики и состояние операции. Отчёт назначения содержит пути компонентов и является личным файлом, защищённым локальным .gitignore; не публикуйте пользовательское назначение как часть исходников.

## Макеты

### Измерение кадра при генерации (разработка)

Локальная генерация выполняется с приоритетом CPU Below Normal для всего дерева worker, включая дочерние движки. Это оставляет обычным UI/аудиопотокам преимущество при конкуренции за CPU; на занятой машине сама подготовка может длиться дольше. Готовые записи и интерфейс этот приоритет не получают.

Release-кандидат поддерживает `app.exe --measure-frames <новая абсолютная папка отчёта> <личный descriptor.json>`. Дескриптор содержит `preferences` с уже установленными моделями, `resources` и `preset_source`; пример с личными путями/голосом в Git не включается. Проверка создаёт отдельную синтетическую библиотеку и использует внешние компоненты только для чтения. Скачивания моделей, нативных окон, реального ввода и воспроизведения нет.

После прогрева 60 секунд проверяются пять страниц настоящего AppWindow, партия из трёх текстов с озвучкой и отмена следующей задачи. Путь замера: timestamp фонового потока → очередь Slint → смена страницы → полный программный кадр 1100×780 в памяти; один запрос до подтверждения кадра, интервал 50 мс. Требуется не менее 300 кадров при активной задаче, p95 ≤100 мс и остановка отменяемой задачи ≤8 секунд. Отчёт содержит все отсчёты, SHA EXE, отдельные память/CPU самого процесса. Это не замер физического ввода, экранного compositor, покоя или доказательство работы на ноутбуке 8 ГБ; дерево ML-процессов измеряется отдельно.

Для адресной диагностики отчёт также разделяет очередь, смену страницы и CPU рендера; watchdog читает CPU/IO UI-потока и счётчики процесса, без приостановки. `KAVYCHKA_TRACE_STACK_HINTS=1` включает только в этом opt-in замере сигналы о долгой фазе для внешнего локального сборщика. Диагностические прогоны с приостановкой тестового потока не считаются замерами производительности.

Контроль политики планирования: собрать `next/tools/frame-load.rs` через `rustc --edition 2024 -O -o <свой frame-load.exe>`, затем вызвать release `app.exe --frame-contention-test <новая папка> <свой frame-load.exe>`. Настоящий AppWindow и собственный нагрузочный процесс намеренно делят один разрешённый логический CPU. Сравниваются Normal и производственный Below Normal Job, проверяется фактический класс приоритета; маска только тестового UI-потока восстанавливается. Программа не меняет системную маску, не открывает окна и не запускает модели. Критерии: исходный максимум >100 мс, в исправленном случае не менее 100 кадров, p95 <50 мс и ни одного кадра >100 мс. Это регрессия конкуренции за CPU; сама по себе не доказывает причину отдельного исторического выброса без его стека.

```powershell
.\work\rust-next-target\debug\kavychka-design-preview.exe overview light "E:\TestData\overview-light.png"
.\work\rust-next-target\debug\kavychka-design-preview.exe overview dark "E:\TestData\overview-dark.png"
.\work\rust-next-target\debug\kavychka-design-preview.exe models light "E:\TestData\models-light.png"
.\work\rust-next-target\debug\kavychka-design-preview.exe library dark "E:\TestData\library-dark.png"
```

Рендер работает в собственной памяти, не открывает пользовательское хранилище и не управляет рабочим столом. Существующие изображения не перезаписывает. Это материал для согласования P2, а не проверка реального окна Windows, доступности или работы кнопок.

## Подготовка Rust-релиза

Workflow `.github/workflows/next-windows.yml` проверяет исходники и worker, собирает Rust-кандидат и portable. Для точного тега `next-vX.Y.Z` версия встраивается в EXE; `next/tools/verify_release.py` сверяет тег с manifest установщика, SHA каждого файла и одинаковый setup внутри portable, затем сохраняет `SHA256SUMS.txt`. Имена/суффиксы иных версий отвергаются.

После успешной проверки того же run workflow готовит **черновик** GitHub release из проверенных артефактов. В публичном канале обновлений черновик не виден. Его публикация выполняется после финальной приёмки; добавление workflow не означает, что он уже выполнен или релиз опубликован. Теги и загрузки в этом изменении не создавались.

Локальная проверка без запуска установщика и без публикации:

```powershell
python -B next/tools/verify_release.py --tag next-v0.1.23 --setup outputs/next/0.1.23/Kavychka-Next-Setup.exe --portable outputs/next/0.1.23/Kavychka-Next-Portable.zip --output work/release-0.1.23.json
```

Выбирай новую папку результата. Существующий `SHA256SUMS.txt` проверяется и не заменяется несовпадающими суммами.
