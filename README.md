# Кавычка

## Предварительная версия Rust + Slint

[Кавычка Next 0.1.27](https://github.com/myjname/kawichka/releases/tag/next-v0.1.27) — новый Windows 11 x64 кандидат. В выпуске доступны `Kavychka-Next-Setup.exe`, portable ZIP и контрольные суммы. Это предварительная версия: ручная и аппаратная приёмка ещё не завершена, стабильный канал прежней версии автоматически на неё не переключается. Версия 0.1.27 содержит кодовые исправления проверенного кандидата 0.1.25, исправление GitHub Actions и сохранение ручных напоминаний прежней версии при отключённой автоматической разминке.

Настройки и записи переносятся в отдельное поколение общего хранилища, установленные модели используются по прежним путям. Перед переходом заверши старую Кавычку через трей. [Инструкция Next](next/README.md) · [проверки и ограничения 0.1.25](docs/RUST-SLINT-CANDIDATE-0.1.25.md). Из исходников новую оболочку запускает `next/Start-preview.bat`; корневой `START.bat` относится к прежнему приложению.

Ниже — описание прежней стабильной версии на WinForms.

Windows-приложение с маскотом, напоминаниями и локальной генерацией текста и речи на русском и английском. Базовые напоминания работают сразу с готовыми фразами и голосом Windows. Для нужного языка должен быть установлен системный голос; локальные модели можно подключить отдельно. Облачные API и сохранение их ключей удалены.

## Запуск

Готовые установщик и portable доступны в [GitHub Releases](https://github.com/myjname/kawichka/releases/latest). Для базовых напоминаний не нужно скачивать модели или устанавливать Python.

В новом интерфейсе v2 тема выбирается в **«Обзор → Тема»**: **«Как в системе»** (по умолчанию), **«Светлая»**, **«Тёмная»**. Выбор применяется сразу и сохраняется отдельно от остальных правок формы. Системный режим реагирует на изменение темы приложений Windows; ручной выбор имеет приоритет. Тема распространяется на настройки, библиотеку, меню и сообщения маскота.

В **«Обзоре»** есть переключатель **«Запускать вместе с Windows»**. В новой установке он выключен; существующий ярлык прежней версии подхватывается. После включения маскот запускается при входе в учётную запись Windows. Подготовка нового дня работает в фоне, пока приложение запущено. Автозапуск принадлежит текущему пользователю и не требует администратора; после запуска новой версии из другой папки существующий ярлык обновляется на её EXE.

Настройки записываются с заменой файла после успешной записи временной копии. Если не удалось сохранить основную форму настроек, она остаётся открытой, сообщает ошибку и сохраняет прежние действующие настройки. Исправь место или доступ к папке и повтори сохранение. Проверка установки тоже завершается ошибкой, если мигрированные настройки невозможно сохранить.

Маскот использует прозрачность с мягкими краями в обеих темах. У стандартной Кавычки есть обычное, говорящее, дразнящее и радостное состояния; после отметки завтрака радостная реакция длится несколько секунд. При паузе появляются решётка и оставшееся время. Загруженные PNG сохраняют полупрозрачность, GIF — анимацию.

Если скачали **исходники с GitHub**, дважды нажмите **`START.bat` в корне репозитория**. Он сам соберёт и откроет приложение. После обновления исходников сборка обновится автоматически; повторные запуски без изменений пропускают сборку. Python вручную устанавливать не нужно. При ошибке окно останется открытым с её описанием. Сохраните всю папку репозитория, а не только батник.

Запустите `Kavychka-Setup.exe` либо распакуйте `Kavychka-portable.zip` и откройте `Kavychka.exe`. Установщик работает без администратора, по умолчанию в `%LOCALAPPDATA%\Programs\Kavychka`. Модели и данные хранятся отдельно от программы — в `%LOCALAPPDATA%\Kavychka`.

В новом окне **«Модели»** выберите текстовую и голосовую модели и нажмите **«Подготовить выбранное»**. Приложение само подготавливает зависимости, показывает текущий этап и позволяет отменить подготовку. Без загрузок доступны готовые фразы и голос Windows. Выбор модели сам по себе не начинает скачивание.

Перед подготовкой проверяются RAM, NVIDIA и поддерживаемая драйвером версия CUDA. В автоматическом режиме для подходящей видеокарты выбирается NVIDIA, иначе CPU; текст и голос проверяются отдельно. Для текста на CPU скачивается только CPU-среда llama.cpp — около 20 МБ, без CUDA-библиотек. Уже установленная совместимая среда используется повторно. Выбор CPU в расширенных настройках имеет приоритет над автоматическим определением. Сведения об устройстве и приблизительная оценка достаточности памяти появляются в «Моделях»; оценка не учитывает память, занятую другими программами. Локальная озвучка на CPU может готовиться долго. Можно выбрать готовые фразы, системный голос или меньшую модель.

Кнопки подготовки и отмены, текущий этап и прогресс закреплены внизу раздела «Модели». Остальные параметры прокручиваются колесом мыши или полосой справа; управление загрузкой остаётся на месте.

Прежние подробные экраны доступны через **«Расширенные»**. На расширенной вкладке «Модели»:

1. В блоке **«Текстовые модели»** выберите модель для дневного списка и, отдельно, для рантайма. По умолчанию в обоих случаях — **Gemma 4 12B**. Для работы не нужно устанавливать вторую текстовую модель. Ни смена выбора, ни сохранение настроек не скачивают модели.
2. В блоке **«Голосовые модели»** по умолчанию выбрана **CosyVoice 3 0.5B** с управлением интонацией. Qwen3-TTS **0.6B** и **1.7B** остаются вариантами для отдельного скачивания. Установите среду голоса NVIDIA либо CPU. Python устанавливается приложением автоматически. Для CUDA нужен подходящий драйвер NVIDIA; отдельный CUDA Toolkit не нужен.
3. Нажмите **«Установить среду текста»**, затем **«Скачать выбранную текстовую»** и кнопку выбранного голоса. Для рантайма установите выбранную для него модель, если она отличается. Для CosyVoice дополнительно нажмите **«Установить среду CosyVoice»**. Нажмите **«Применить выбор»**. Остальной список скачивать не требуется.

Все обсуждённые текстовые варианты доступны в обоих списках:

| Модель | Файл весов | Проверка русских напоминаний |
|---|---:|---|
| Gemma 4 12B, QAT Q4_0 | 6,98 ГБ | Из проверенных лучше справлялась с заданием |
| Gemma 4 E4B, QAT Q4_0 | 5,15 ГБ | Быстрее; чаще требует ручного отбора |
| Qwen3.5 4B, Q4_K_M | 3,01 ГБ | Проверена; заметные ошибки русского |
| Qwen3.5 9B, Q4_K_M | 6,17 ГБ | Проверена; заметные ошибки русского |
| Ministral 3 8B Instruct, Q4_K_M | 5,20 ГБ | Проверена; бывают неуместные образы |
| QVikhr 3 8B Instruction, Q4_K_M | 5,03 ГБ | Проверена; ошибки форм слов и обращения |
| Saiga-Llama3 8B, Q4_K | 4,92 ГБ | Добавлена для выбора, не скачивалась и не проверялась |

Это оценка одного задания, а не общий рейтинг моделей. Уже установленные варианты показывают «Установлено · работает офлайн». Для сравнения сохраните выбор и создайте «Новую партию». Готовые фразы автоматически не заменяются.

Загрузки закреплены по ревизиям и SHA-256. Кнопка повторной загрузки проверяет существующие файлы и продолжает `.part`. Кнопка «Отменить очередь» останавливает генерацию или загрузку; для повторного запуска нажмите ту же кнопку установки. Во время распаковки и установки pip процент может быть неопределённым, при этом отображается текущий этап.

Объёмы файлов (десятичные ГБ): Python около 11 МБ, PyTorch CUDA 2,86 ГБ, Gemma 4 12B 6,98 ГБ, CosyVoice 3 5,43 ГБ, её дополнительные зависимости около 0,2 ГБ загрузки, llama.cpp 0,58 ГБ. Рабочая установка Gemma + CosyVoice со средой занимает примерно **19 ГБ**, без установочных кэшей и пользовательского аудио. Если понадобится Qwen: 0.6B — ещё 2,52 ГБ, 1.7B — ещё 4,54 ГБ. CPU-среда компактнее, но синтез медленнее. После установки генерация и прослушивание работают без интернета.

Gemma использует официальные QAT GGUF Google; остальные источники и закреплённые ревизии перечислены в `assets/components.json`. Для Gemma, Qwen3.5, Ministral и QVikhr авторы указывают Apache 2.0; для Saiga действуют условия автора и базовой Llama 3, см. [карточку Saiga](https://huggingface.co/IlyaGusev/saiga_llama3_8b_gguf). Используется отдельный локальный процесс llama.cpp с контекстом 4096 и отключённым thinking. Текстовая модель выгружается перед загрузкой TTS; обе одновременно в VRAM не держатся. При завершении Python-процесса Windows автоматически завершает и дочерний генератор. Для CUDA текста нужен драйвер, поддерживающий комплект CUDA 13.4; отдельный CUDA Toolkit не нужен. Режим CPU доступен в выборе устройства.

На RTX 4080 SUPER 16 ГБ в проверке коротких русских реплик Gemma 4 12B давала более связный русский, чем проверенные Qwen3.5 4B/9B, Ministral 3 8B и QVikhr 3 8B. Это оценка выбранного задания и пользовательского описания персонажа. Без Flash Attention, CUDA Graphs и повторного использования кэша выполнено 25 запросов: медиана 3,94 с, запуск нового процесса 5,11 с, прирост общей занятой GPU-памяти около 7,45 ГиБ. Ускоренный режим однажды завершился ошибкой CUDA и в приложении отключён. Это замеры другой карты, не RTX 5070; объём файла не равен расходу VRAM. Наблюдаемый расход оставляет запас относительно 12 ГБ, но другие приложения тоже занимают память.

## Интонация CosyVoice

В **«Модели → Голосовые модели → Подача CosyVoice»** по умолчанию есть «Авто», «Уверенно», «Спокойно» и «С лёгкой усмешкой». Свои подачи можно добавлять, редактировать и удалять; «Авто» выбирает только из текущего списка. После изменения выбранной подачи нажмите **«Применить выбор»**.

CosyVoice генерирует речь с командой подачи через `inference_instruct2`: это позволяет задавать эмоцию, темп и мягкость голоса. Для собственной инструкции лучше использовать английский, например `Speak warmly, slowly, with a subtle smile.` Лимит — 600 символов. Инструкция передаётся отдельно от произносимого текста и не зачитывается. Следование команде и сходство с голосовым референсом оцениваются на слух.

**«Авто»** просит выбранную текстовую модель подобрать подачу для каждой новой фразы. Сначала создаются текст и направление подачи, затем текстовая модель выгружается и загружается голосовая. При использовании готовых фраз текстовая модель не нужна: приложение выбирает подачу из текущего списка с учётом категории и последних записей. Такой же выбор используется при неподходящем ответе классификатора; при наличии выбора одна подача не повторяется три раза подряд. Результат сохраняется в библиотеке в колонке **«Подача»** и в ZIP-метаданных.

Инструкция интонации входит в ключ аудиокэша. Изменение подачи создаёт другое аудио; готовые записи сами не заменяются. Для старой фразы выберите её и нажмите **«Озвучить заново»**. Новая партия и рантайм используют текущие настройки. У **Qwen3-TTS Base** отдельная команда эмоции отсутствует, поэтому эта настройка к ней не применяется. CosyVoice работает отдельным процессом с закреплёнными зависимостями и не меняет библиотеки Qwen.

## Общее хранилище и обновления

В v2 приложение проверяет новые публичные GitHub Releases (проверку можно выключить в «Обзоре»). О новой версии сообщают маскот и пункт «Обновить» в настройках. Установка запускается после выбора пользователя; загрузку можно отменить в «Моделях». Пакет проверяется по размеру и SHA-256, а каждый его файл — по манифесту. Перед заменой установщик ждёт завершения приложения и сохраняет прежнюю программу и изменяемые настройки. Затем новая версия проверяет интерфейс и миграцию SQLite без загрузки моделей. При ошибке возвращаются предыдущие файлы, настройки и библиотека; сохраняются две последние резервные копии рядом с папкой приложения. Незавершённая установка восстанавливается при повторном запуске установщика. Пользовательские модели и записи не включаются в пакет и при обновлении не переносятся.

По умолчанию все версии под одной учётной записью Windows используют **`%LOCALAPPDATA%\Kavychka`**. Путь по умолчанию сохранён. Чтобы выбрать другой диск, откройте **«Модели → Изменить папку хранилища»** и укажите пустую папку. Расположение EXE и Git-репозитория на этот выбор не влияет.

Приложение останавливает свой локальный процесс, копирует модели, среды, библиотеку, аудио и настройки, проверяет SHA-256 копий и целостность SQLite. Новый путь сохраняется только после успешной проверки; затем удаляются старые неизменившиеся файлы. Перенос можно отменить до переключения, исходные данные сохранятся. Занятые или изменившиеся файлы могут остаться в старой папке — об этом сообщается. Существующая непустая папка и вложение в текущее хранилище не допускаются.

Выбор хранится в маленьком `%LOCALAPPDATA%\Kavychka-storage.json` и автоматически читается последующими версиями. Если выбранный диск отключён, приложение сообщает об этом и не начинает повторную загрузку в C. Без файла выбора используется прежняя стандартная папка. Внутри хранилища:

* `models` — модели текста и речи;
* `runtime` — Python и библиотеки;
* `llama` — среда локального генератора текста;
* `cosy` — отдельные зависимости и закреплённый исходный код CosyVoice;
* `audio` — FLAC-записи;
* `library.sqlite3` — фразы, разрешения, дневные планы и история выдачи;
* `settings.json` — настройки приложения;
* `reminder-state.json` — активная серия напоминаний, отметка и срок следующего повтора;
* `downloads` — скачанные установочные файлы и незавершённые загрузки.

Путь показан на вкладке «Модели», там же есть «Открыть папку данных». Обновляйте программу в прежней или новой папке: модели, библиотека и настройки подхватятся автоматически, переносить `data` вручную не нужно. Новая модель или удалённые компоненты могут потребовать отдельной загрузки.

Первый запуск обновлённой версии автоматически импортирует старую `data` рядом с её EXE и данные прежнего установщика из `%LOCALAPPDATA%\Programs\Kavychka\data`. Настройки v4 из `%LOCALAPPDATA%\KavychkaBreaks` тоже поддерживаются, поля API-ключей отбрасываются. Перенос локальный, с прогрессом; старые файлы сохраняются как резервная копия. Поэтому первый перенос требует свободного места в общем хранилище. При отмене оригиналы остаются целыми, повторный запуск использует уже скопированные файлы.

Библиотека переносится через SQLite backup с учётом WAL. При объединении нескольких найденных библиотек сохраняется история проигранных и удалённых фраз; существующие настройки и ручные исключения общего хранилища имеют приоритет. Завершённые источники отмечаются, чтобы не импортировать старую копию повторно. Произвольные старые portable-папки на других дисках не сканируются: для первого импорта такой версии запустите обновлённый EXE из её прежней папки, после этого хранилище уже общее.

## Дневной план и рантайм

В «Расписании» задаются дни, рабочие часы, интервалы, еда и часовой пояс. По умолчанию перерывы и еда включены в будни, а часовой пояс берётся из Windows. Разминка независима от рабочих дней: кнопка «Я позавтракала / позавтракал» запускает отдельный таймер, по умолчанию на два часа, включая выходные.

В «Моделях» есть галочка **«Рантайм»**:

* **Выключена:** объём предварительной подготовки рассчитывается из оставшихся событий дня и повторов. Успешные тексты и записи сохраняются, недостающие догенерируются с паузами между попытками. Перезапуск продолжает подготовку. Каждая готовая запись выдаётся один раз. При новом дне старое аудио удаляется, тексты остаются для защиты от повторов.
* **Включена:** при напоминании запускается новая генерация. Сообщение появляется сразу; если модель не успевает за несколько секунд, используется готовая запись или системный голос. Запоздавший результат остаётся для следующих напоминаний и не запускает вторую озвучку. Отметка «Я встаю» блокирует запоздалую выдачу. Если текст создан, а голос завершился ошибкой, приложение повторяет только озвучку, в том числе после перезапуска.

По умолчанию тяжёлая генерация откладывается во время полноэкранного приложения. Показ маскота, сообщения, сигнал и голос настраиваются независимо от этого ограничения. Если модели не готовы или закончились записи, напоминание остаётся доступным через запасную фразу и Windows.

Подготовка учитывает приоритет еды и разминки над перерывом: совпадающие события не создают лишние записи, а повторы ограничены рабочими часами и следующим событием. Ближайшие записи готовятся первыми. В расширенных настройках можно отключить автоматическую подготовку или автоматическое разрешение новых дневных записей. При ручном отборе кандидаты ждут решения и после перезапуска; кнопка «Исключить» запрашивает замену, «Оставить» разрешает воспроизведение.

Сообщение остаётся до отметки. По умолчанию кнопка «Я встаю» скрывает сообщение, а завершение перерыва проверяется по неактивности мыши и клавиатуры. Допускаются короткие движения и три случайных клика за весь пятиминутный период; набор текста, прокрутка и продолжительное движение считаются активностью. Порог, число кликов, доверие кнопке и повторы настраиваются. По умолчанию у перерывов и разминки три дразнящих повтора, у еды повторов нет. Мат выключен.

Серия напоминаний сохраняется отдельно в общем хранилище: текст, отметка, число уже отправленных повторов и срок следующего. При быстром перезапуске, если последнее сохранение состояния было не более пяти минут назад, неподтверждённое сообщение возвращается без сигнала и озвучки; повторно фраза из библиотеки не расходуется. Подтверждённое сообщение остаётся скрытым. Будущий таймер повтора сохраняет прежний срок, а повтор, просроченный более чем на пять минут, пропускается без накопления долга. Состояние обновляется при действиях, выходе и не чаще раза в 30 секунд в фоне. После завершённого периода неактивности повторы прекращаются, даже если ты уже вернулась / вернулся к клавиатуре; открытое сообщение всё равно ждёт отметки.

При системном переходе в сон старая озвучка останавливается. Сон не короче настроенного периода неактивности завершает прежнюю серию, а отложенные события, уже покрытые отдыхом, не догоняют после пробуждения. Отметка перехода в сон тоже сохраняется на случай перезапуска процесса.

Ручные партии, выбор количества, отбор кандидатов, «Подготовить день» и повторная озвучка доступны в расширенных настройках. Это отдельные инструменты управления библиотекой. В меню маскота есть паузы на 15/30/60 минут, до завтра и до ручного включения; во время паузы отображаются решётка и таймер.

В **«Обзоре → Фразы на сегодня»** и в меню маскота доступно отдельное окно дневного списка. Оно работает и с локальными моделями, и без них: можно прослушать фразу, оставить или исключить её, создать дополнительную партию нужного размера и выбрать обычные либо дразнящие фразы. **Ctrl+A** выделяет весь список для повторной озвучки и других групповых действий. Для локального голоса есть «Озвучить заново»; экспорт ZIP сохраняет выбранные записи, а при отсутствии выделения — весь показанный список.

В базовом режиме заранее составляется список из встроенного банка готовых фраз и сочетаний. Одна и та же формулировка в течение дня повторно не выдаётся; перезапуск сохраняет отметки. Новый день получает отдельный список, история прежних дней остаётся в `builtin-days` общего хранилища. Предпочтение отдаётся вариантам, которых ещё не было в истории. Банк конечен; для новых авторских формулировок нужен генератор текста. Голос Windows читает фразы при воспроизведении, поэтому его ZIP содержит тексты. Локальная TTS сохраняет готовое аудио в архив вместе с текстами.

В этом окне можно отключить автоподготовку и автоматическое разрешение новых дневных фраз. При ручном отборе кандидаты остаются в списке до решения пользователя, включая перезапуск. Прослушивание не расходует запись. После подключения текстовой модели встроенная текстовая история тоже учитывается в проверке повторов. Явная полная очистка библиотеки удаляет эту историю вместе с остальными текстами; обычная ежедневная очистка удаляет только старое аудио.

Ручная команда «Размяться сейчас» или проверка голоса работает и во время паузы; автоматические напоминания при этом остаются выключенными. Повторная установка паузы останавливает текущую озвучку и сообщение.

## Характер персонажа

В **«Персонаже»** голос, характер и внешность выбираются независимо. «Просмотр и настройка» открывает отдельное окно: описание можно редактировать, голосовые записи — прослушивать и снабжать расшифровкой, картинку — посмотреть и выбрать способ показа. Там же доступны экспорт и удаление пользовательского пресета. Стандартный вариант остаётся первым пунктом списка; редактирование стандартного голоса или характера создаёт отдельную копию.

По умолчанию используется оригинальная Кавычка: дружелюбный персонаж с сухим юмором, без романтики, угроз и мата. Описание ограничено 4000 символами. Загруженные пресеты хранятся в общей папке данных вне программы и Git. Переносимый файл `.kavychka` содержит только выбранный компонент и его медиа, без моделей, расписания и ключей. Существующий пользовательский характер при обновлении переносится в отдельный пресет.

Для голоса можно импортировать до восьми подготовленных записей в распространённых аудиоформатах; приложение само переводит их в FLAC. Нужны 1–30 секунд, желательно 10–20 секунд чистой речи одного человека, без музыки, шума, эха и обрывов. Качество и права на исходную запись проверяет пользователь. При первом преобразовании отдельно скачивается небольшой декодер. CosyVoice чередует записи; Qwen использует первую. Для Qwen точная расшифровка включает режим с речевым контекстом; без неё используется копирование тембра. Изменение расшифровки учитывается в кэше.

Для внешности подходят PNG, JPEG, GIF и WebP. GIF сохраняет анимацию, WebP преобразуется в PNG. Лист Codex имеет 1536 × 1872 пикселя: восемь столбцов и девять строк по 192 × 208. Если файл такого размера — обычная картинка, выберите соответствующий способ показа. Пауза с решёткой применяется к любой внешности.

Совместимость листа сверена с [публичным контрактом Codex](https://github.com/openai/skills/blob/main/skills/.curated/hatch-pet/references/codex-pet-contract.md), режимы голосового референса — с [интерфейсом Qwen3-TTS](https://github.com/QwenLM/Qwen3-TTS/blob/main/qwen_tts/inference/qwen3_tts_model.py).

Описание влияет на текст и его ритм, но не меняет голосовой референс. В автоматическом режиме CosyVoice оно также учитывается при выборе подачи. У Qwen3-TTS Base отдельной инструкции эмоции из этого поля нет. Новый персонаж с другим описанием продолжит звучать выбранным голосом. Следование характеру зависит от выбранной текстовой модели; результат можно отбирать в библиотеке.

## Библиотека и звук

В библиотеке отображаются дата, категория, состояние и полный текст выбранной строки. Поддерживаются множественный выбор, прослушивание, остановка, «Оставить», «Исключить», удаление и повторная озвучка выбранным размером модели. Прослушивание в библиотеке не расходует запись для уведомлений.

«Новый текст» создаёт отдельного кандидата той же категории, сохраняя исходную запись. «Озвучить заново» использует выбранную TTS-модель и новый seed; предыдущее аудио заменяется только после успешного синтеза.

Аудио хранится в **FLAC PCM16**, без потерь. При воспроизведении локальный сервер декодирует его в WAV для Windows. Ключ кэша учитывает текст, модель, ревизию, профиль голоса и параметры синтеза. Экспорт ZIP содержит FLAC-файлы и `phrases.json`; без выделения экспортируется вся библиотека. Очистка защищает все живые записи, включая кандидатов; удаляет только аудио удалённых строк и временные файлы. История текстов остаётся для проверки повторов.

В комплекте используется нейтральный синтетический голосовой референс. Пользовательские записи добавляются отдельно и в дистрибутив не входят.

Текстовые модели иногда ошибаются в грамматике, образах и обращении; быстрая E4B чаще требует ручного отбора. Есть проверка языка, категории, длины, запрета мата и повторов, но это не гарантирует литературное качество. Библиотека позволяет исключать неудачные варианты. Одинаковые нормализованные тексты не добавляются повторно, включая ранее удалённые. Qwen3-1.7B больше не предлагается для новой генерации; ранее созданные записи продолжают воспроизводиться без весов старой модели.

Новые реплики не могут начинаться с «Пора» или «Ну, пора»: такие кандидаты генерируются заново. Дополнительно сравниваются последние 500 текстов всей библиотеки, включая исключённые и удалённые. Замена «пообедать» на «поужинать», названий приёмов пищи, «утром» на «вечером» и близкие правки одной формулировки распознаются как повтор. Проверяются также одинаковые части предложения от пяти слов, общие фрагменты от восьми слов и повтор первых трёх слов среди последних восьми записей. Шесть последних реплик передаются генератору как примеры того, что не нужно повторять. При повторной попытке меняется способ построения реплики. Это проверка текстовых шаблонов, а не полное понимание смысла: свободный пересказ может пройти. Если за шесть попыток подходящей реплики нет, генерация показывает ошибку; готовый повтор вместо неё не подставляется. Ранее созданная библиотека автоматически не очищается.

## Разработка

Нужны Windows 10/11 x64 и .NET Framework 4.8. Сборка использует системный `csc.exe`, без NuGet:

Для обычного запуска из исходников достаточно `START.bat`. Параметр `START.bat -Rebuild` принудительно пересобирает приложение; `START.bat -BuildOnly` собирает без запуска окна. Данные и скачанные модели при пересборке сохраняются.

```powershell
.\scripts\build.ps1
```

Результат — `outputs\Kavychka`, `outputs\Kavychka-portable.zip`, `outputs\Kavychka-Setup.exe`. Модели, runtime, библиотека и аудио не включаются в сборку и Git. Общий размер исходников с референсом — меньше мегабайта.

Проверки:

```powershell
python -B -m unittest discover -s tests -v
Start-Process .\outputs\Kavychka\Kavychka.exe -ArgumentList '--self-test', "$PWD\work\schedule-tests.txt" -Wait
.\scripts\test-native.ps1
.\scripts\test-startup.ps1
.\scripts\test-update.ps1 -Python python
```

`test-update.ps1` создаёт отдельную тестовую установку внутри `work`, проверяет перенос настроек и базы, ожидание старого процесса и откат после заведомого сбоя нового EXE. Успешные тестовые копии удаляются; при ошибке остаются для разбора. Пользовательская библиотека и установленные модели не используются.

`test-native.ps1` пересобирает C#-проверки перед запуском, чтобы старые тестовые EXE не ссылались на изменившиеся методы. Для проверки конвертации аудио передайте `-Ffmpeg` с путём к Windows-декодеру из imageio-ffmpeg 0.6.0. Без этого параметра аудиоконвертация пропускается, остальные проверки запускаются.

Проверка v2 с установленными Gemma и CosyVoice:

```powershell
python -B tests/real_v2.py --models-data "$env:LOCALAPPDATA\Kavychka" --python "$env:LOCALAPPDATA\Kavychka\runtime\python.exe" --work work/real-v2-check
```

Она использует уже установленные компоненты без копирования весов и с запретом установки в исходную папку. Отдельная библиотека проверяет русские обычные и дразнящие фразы, английский рантайм, независимые пресеты, однократную выдачу, экспорт, перезапуск и удаление старого аудио с сохранением текстов. Папка `--work` должна быть новой; там остаются отчёт и WAV-примеры.

Параметр `--manual-batches` проверяет сценарии нового дневного окна: генерацию текста с системной озвучкой и готовый текст с локальной TTS без установленной текстовой модели. Дополнительно `--native-history путь-к-тестовой-builtin-days` копирует встроенную историю из изолированного теста для проверки защиты от повторов после подключения модели.

Полный тест с настоящими моделями (нужны Gemma 4 12B и CosyVoice со средами):

```powershell
python -B tests/real_inference.py --models-data "$env:LOCALAPPDATA\Kavychka" --python "$env:LOCALAPPDATA\Kavychka\runtime\python.exe" --work work/new-integration-check
```

Этот тест создаёт отдельную библиотеку, блокирует внешние сетевые соединения в движке, генерирует 13 записей, проверяет отбор, выдачу без повторов, ZIP, перезапуск, рантайм, смену интонации и её автоподбор. Для дополнительного сравнения Qwen скачайте обе её версии явно и добавьте `--compare-qwen` к команде теста. Каталог `--work` должен быть новым. Результаты и WAV лежат внутри него, пользовательская библиотека не меняется. Результаты выполненной проверки описаны в `docs/VALIDATION.md`.

Бэкенд использует stdlib HTTP/SQLite и закреплённые зависимости из `backend/requirements.txt`. PyTorch/torchaudio ставятся отдельно из проверенных официальных wheels. Сервис слушает только `127.0.0.1` на случайном порту; каждое обращение требует одноразового токена сессии. Токен передаётся через окружение, не через командную строку; запросы с browser Origin отклоняются. Генерация последовательная: текстовая модель выгружается перед озвучкой, чтобы экономить VRAM.

Для разработки можно задать `KAVYCHKA_PYTHON` на уже настроенный Python и `--data-dir "папка"` для отдельной библиотеки. Явный `--data-dir` и `--preview` изолированы от общего хранилища: пользовательские данные туда не импортируются. Настройка `model_paths` локального API позволяет переиспользовать внешние модели; явные внешние пути разработчика сохраняются. Обычной установке ручное редактирование настроек не требуется.

Полная проверка на Windows: установите Python 3.12, выполните `python -m pip install -r tests/requirements.txt`, затем `powershell -ExecutionPolicy Bypass -File scripts/test.ps1`. Сценарий собирает приложение и установщик, проверяет интерфейс, обычный запуск, восстановление, перенос данных, откат и локальный API. Пользовательское хранилище и автозапуск Windows не меняются; модели не скачиваются. Тестовые файлы создаются в `work`. В GitHub Actions этот же сценарий запускается перед выпуском. Тег `vX.Y.Z` должен соответствовать версии в `src/AssemblyInfo.cs`; после успешных проверок workflow публикует установщик, portable и SHA-256 в GitHub Releases. Приложение получает обновления из этих выпусков.

`test-startup.ps1` запускает обычную цепочку старта приложения без тестового отключения маскота и наблюдения за активностью, в двух отдельных процессах с изолированными данными. Проверяются первый вход, сохранение, повторный вход и запасное напоминание без Python/моделей. Звук отключён; реальный автозапуск Windows не меняется. Отчёты и снимок первого окна остаются в `work/first-run-*`.

`--preview путь.png --library|--models|--settings [--bottom]` проверяет раскладку и создаёт снимок средствами самого приложения. `--setup-smoke результат.json --data-dir папка [--install-runtime]` проверяет локальный backend. `Kavychka-Setup.exe --silent --target папка` распаковывает приложение без запуска и без изменения автозагрузки.

Не добавляйте в Git `data`, `work`, `outputs`, веса моделей, окружения, ключи, `.env` и пользовательские настройки. При переносе v4 импортируются только известные настройки расписания; поля API-ключей отбрасываются.

## Если установка голосовой среды прервалась

Обновите приложение, полностью закройте его через трей и запустите `START.bat`, затем повторите установку нужной среды. Установщик заранее подготавливает закреплённые версии инструментов сборки и использует их без временной build isolation, сохраняя изоляцию встроенного Python. Уже скачанные архивы повторно используются после проверки SHA-256.

Полный вывод установочных команд сохраняется в `<хранилище>\logs\runtime-install.log` и `<хранилище>\logs\cosy-install.log`. Повторные попытки дописываются; при сбое приложение показывает последние непустые строки и путь к журналу. Модели, настройки и библиотеку для повторной установки удалять не нужно.
